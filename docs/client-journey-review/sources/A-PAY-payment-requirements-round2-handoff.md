## 1. 文档目的

本文件把本轮支付需求访谈中已经确认的产品决策保存为可交接基线，供下一位同事继续完成：

1. 完整用户流程和页面/状态清单；
2. 支付 UI 设计与评审；
3. 第二轮实施编排计划；
4. 后续任务拆分、实现和验收。

本文件不是现有 [`implementation-orchestration-plan.md`](./implementation-orchestration-plan.md) 的修改稿，也不授权直接进入编码。现有计划先按原边界完成；本文件描述其后的第二轮商业化能力。

## 2. 背景与现状

### 2.1 当前仓库事实

- ProductSpace 只有 `personal` 和 `enterprise` 两类；Creator Circle 不是 ProductSpace。
- 当前仓库的 `User.monthlyQuotaTokens`、`QuotaPeriod` 和 `UsageRecord` 是按用户和 Token 计量的旧配额能力，不是 ProductSpace 付款主体、积分钱包或支付账本。
- 当前 POL-94 工作树尚无充值订单、Credit Wallet、不可变积分流水或真实支付通道实现。
- 现有计划中的 POL-89 负责 ProductSpace 付款主体、预算和最小计量；POL-91 负责圈子订阅与内容收入账本；POL-94 位于既有 G5 主 DAG 之外。
- 现有客户端支付由系统浏览器承载，Polo 客户端只负责入口、任务上下文和支付完成后的状态恢复。
- App 是由 FDE 制作并下载到用户设备运行的本地 Web App；Polo 启动其 localhost 页面，并通过本地 API 提供 AI 算力，但不控制 App 内任务页面。

### 2.2 本轮要解决的问题

此前尚未统一以下商业和用户体验问题：

- 用户购买什么、积分代表什么；
- Polo 助手和本地 Web App 如何按实际用量扣费；
- 个人与企业如何隔离余额、权限和供应商凭证；
- 微信/支付宝支付、退款、发票、拒付和异常恢复如何处理；
- 圈子订阅、创作者定价、分成和算力费用如何分离；
- 客户端、企业管理端、创作者工作台和平台运营端分别承担什么职责。

### 2.3 成功标准

- [ ] 下一阶段可以仅依据本文件画出个人算力、企业算力和圈子订阅的完整用户流程。
- [ ] 任何订单、积分、内容权益、创作者收入和供应商消耗都能确定唯一责任主体和权威账本。
- [ ] 正常支付、处理中、重复回调、迟到支付、退款、拒付、对账差异和关闭善后都有确定行为。
- [ ] 用户界面不暴露模型、Token 或供应商细节，但能在付款和执行前形成明确预期。
- [ ] 新设计不会把旧 Token 月配额、Creator Circle 或本地 Workspace 错当成新支付模型。

## 3. 范围、顺序与非目标

### 3.1 交付顺序

第二轮分两个增量交付：

1. **增量 A：算力支付**
   - 个人和企业算力商品；
   - 试用积分、30 天算力套餐、永久加油包；
   - ProductSpace 积分账本、预占、扣减、退款和对账；
   - Polo 助手和本地 Web App 按实际用量计费；
   - 微信 Native 与支付宝二维码支付。
2. **增量 B：圈子支付**
   - 圈子付费订阅；
   - 创作者定价、收入账本、退款归责和结算；
   - 创作者工作台与平台运营端财务状态。

两类支付共用订单、支付通道、回调、查询、退款、发票和异常处理基础设施，但必须使用独立的权益/资金账本：

- 算力订单产生 ProductSpace 积分；
- 圈子订单产生个人空间的圈子内容权益和创作者待结算收入；
- 两者不能合并购物车、组合付款或互相抵扣。

### 3.2 当前版本明确不做

- 自动扣费、委托代扣或自动续费；
- 海外货币、外卡、汇率和海外税务；
- 移动端同设备 H5/JSAPI/App 拉起支付；
- 单独购买 App 或 Skill；
- 使用积分购买圈子、App 或 Skill 内容；
- 创作者设置算力价格、打包算力或替圈子成员承担算力；
- 个人用户自行上传、导入或旁加载 App/Skill；
- App/Skill 在个人空间与企业空间之间复制或共享；
- 企业为成员批量购买圈子、圈子席位或企业圈子许可证；
- 企业成员/成员组独立积分配额；
- 企业授信、月结或先用后付；
- 个人月度消费上限；
- 优惠券、限时折扣、赠送比例和加油包阶梯单价；
- 按结果付费；
- 固定价 App、操作级固定报价和整 App 一次性固定计费；其实现时间待定；
- 助手调用 App；
- 复杂跨空间审批和流转策略；
- 在本阶段锁定最终 API 路径、供应商 Key 技术方案或具体价格数字。

## 4. 核心领域不变量

### 4.1 ProductSpace 是资金、内容和运行边界

- 普通业务账号恰好有一个 `personal ProductSpace`，产品界面称“我的空间”。
- 一个 Enterprise 恰好有一个 `enterprise ProductSpace`。
- 每笔算力订单、积分批次、预占、消耗、退款和执行都必须绑定不可变的 `productSpaceId`。
- 个人空间积分不能转给企业空间；企业空间积分不能转给个人或其他企业。
- 当前空间决定 App/Skill 目录、数据、权限、供应商凭证和算力承担方。

### 4.2 一个空间只采用一种内容供给机制

- 个人空间由 Polo 内置能力和用户订阅的多个创作者圈子提供内容。
- 企业空间只由该企业配置和分发 App/Skill。
- 企业不能订阅、持有、续费或接收圈子权益。
- 圈子订阅和圈内 App 只属于个人空间；圈内 App 只能扣该个人空间积分。
- 企业 App/Skill 只能在企业空间运行并扣企业积分。
- 圈子不是空间切换项；多个圈子的内容聚合进同一个“我的空间”。

### 4.3 作品分发与前端来源展示

- 同一个 App/Skill 作品不能分发到多个圈子。
- 创作者要在多个圈子提供相似能力时，必须分别重新上传，形成不同作品 ID、版本和生命周期。
- 后端必须保存作品、圈子和企业来源，用于授权、撤销、退款、审计和安全治理。
- 普通 App/Skill 消费界面不额外展示创作者或圈子来源标签；当前 ProductSpace 标识承担个人/企业来源说明。
- 圈子详情、订阅确认、订单和退款页面仍必须明确展示目标圈子，因为这些页面本身处理圈子关系和资金。

## 5. 角色与权限

| 主体 | 可以做 | 不可以做 |
|---|---|---|
| 个人用户 | 购买个人算力商品、管理个人积分、订阅多个圈子、申请个人退款和发票、导出个人流水 | 使用企业余额购买个人内容、转移积分、上传/旁加载 App/Skill |
| Enterprise Owner | 购买企业算力、设置企业月度总预算、查看总余额和成员汇总、退款、发票、导出、处理关闭善后 | 把企业积分转给个人、用企业空间订阅圈子 |
| Enterprise Manager | 查看企业算力可用/不足/本月额度达上限状态，使用企业授权能力 | 查看任何企业积分金额、消耗记录或财务详情；充值、退款、发票、查看成员用量、修改企业预算 |
| Enterprise Member | 查看企业算力可用/不足/本月额度达上限状态，使用企业授权能力 | 同 Manager 的财务禁区 |
| Creator Owner | 设置圈子订阅价格、管理成员和内容、查看圈子聚合经营与收入、管理收款账户 | 查看成员余额、对话、文件、App 输入输出；设置算力价格；替成员支付算力 |
| 平台工作人员 | 处理支付异常、退款、拒付、对账、补偿、结算和治理 | 直接改写原订单、历史积分、历史用量或创作者收入记录；默认读取用户业务内容 |
| 实际扫码付款人 | 完成外部支付 | 因代付获得 ProductSpace 的余额、退款、发票或订单管理权限 |

企业充值、退款、发票资料修改均为 Owner-only；退款和修改发票抬头要求重新验证身份。当前版本不做双人审批或财务角色委派。

## 6. 算力商品与积分模型

### FR-001：积分只代表 AI 算力

- **优先级**：P0
- **描述**：积分是 Polo 内部统一算力计费单位，只能用于 Polo 助手、App 和 Skill 的 AI 算力消耗。
- **验收标准**：
  - [ ] 积分不能支付圈子订阅或内容费用。
  - [ ] 用户界面不展示积分与人民币、Token、模型或供应商的一一换算。
  - [ ] App Catalog 或 App Index 只展示“按实际用量计费”，不展示虚构的预估价格、价格区间或固定报价。
  - [ ] Polo 助手对话和 App 结果页面均不展示积分、余额、消耗或结算信息。
  - [ ] Polo 助手和独立 App 的实际消耗只在支付中心的“积分 -> 消耗记录”中展示。

### FR-002：试用积分

- **优先级**：P0
- **描述**：完成手机号验证的个人用户可领取一次 7 天试用积分。
- **验收标准**：
  - [ ] 每个个人用户仅一次，企业空间无试用积分。
  - [ ] 风控判定高风险时仍允许登录和付费，但不发试用积分。
  - [ ] 试用积分不可退款、转让或购买内容。
  - [ ] 试用批次优先于更晚到期批次消耗。
  - [ ] 额度只描述为可完成少量体验，不承诺固定对话次数或任务数量。

### FR-003：30 天算力套餐

- **优先级**：P0
- **描述**：首版提供一款主力“30 天算力套餐”，不使用“会员”名称，也不承诺会员权益。
- **验收标准**：
  - [ ] 有效期从支付渠道确认成功的 `paidAt` 起连续计算 30×24 小时。
  - [ ] 到期时间使用北京时间作为业务基准，并向用户展示年月日和时分。
  - [ ] 支付成功到积分到账之间不顺延有效期。
  - [ ] 一个 ProductSpace 同时最多一个有效套餐。
  - [ ] 套餐积分提前用完时仍保持有效到原到期时刻，但只提示“套餐积分已用完，可购买加油包”。
  - [ ] 套餐有效期内不能再次购买套餐；即使积分用完也只能买加油包。
  - [ ] 到期未用积分失效，不结转、不自动退款。
  - [ ] 手动续费，不自动扣款。

### FR-004：永久加油包

- **优先级**：P0
- **描述**：首版提供三种长期有效的积分加油包，可独立购买，不要求先有 30 天套餐。
- **验收标准**：
  - [ ] 三档加油包每积分单价相同，不做数量折扣。
  - [ ] 企业可展示更大数量规格，但每积分价格不因企业或数量降低。
  - [ ] 加油包积分长期有效。

### FR-005：商品相对定价

- **优先级**：P0
- **描述**：30 天套餐以有效期换取更低单位价格；加油包以永久有效换取灵活性。
- **验收标准**：
  - [ ] 30 天套餐每积分价格预计比加油包低 15%–25%，最终比例由成本与毛利测算决定。
  - [ ] 商品页展示人民币价格、积分数量、有效期和使用范围，不宣称现金等价或保证任务次数。
  - [ ] 具体金额和积分数量由运营配置提供，不写死在客户端。

### FR-006：批次与消耗顺序

- **优先级**：P0
- **描述**：所有积分按来源批次记录，消耗时优先使用最早到期批次。
- **验收标准**：
  - [ ] 预占和实际扣减都能追踪到具体批次。
  - [ ] 释放预占时恢复原批次和原到期时间。
  - [ ] 已到期积分不得因释放、重试或对账而重新变为可用。

### FR-007：积分精度

- **优先级**：P0
- **描述**：账本使用高精度小数，避免小额调用被逐次向上取整。
- **验收标准**：
  - [ ] 内部账本保留高于四位小数的精度。
  - [ ] 头像菜单的可用积分余额显示四位小数。
  - [ ] 正式消耗与返还记录固定显示四位小数；小于 `0.0001` 时显示“不足 0.0001 积分”，不向上取整。
  - [ ] Polo 助手不设置“每轮至少 1 积分”的最低消费。

## 7. 算力计费

### FR-008：Polo 助手按实际消耗计费

- **优先级**：P0
- **描述**：自由对话无法事先保证总价，按每轮实际消耗扣积分。
- **验收标准**：
  - [ ] 服务端在每次发送前使用平台内部单轮保护上限；普通用户不查看、不调整，对话输入区不显示上限或积分。
  - [ ] 正常完成的回答不显示“已结算”、实际消耗、剩余积分或任何计费图标；即使完成后余额恰好为零，也不把本轮标记为中断。
  - [ ] 用户主动中止时保留已返回内容，回答末尾只显示“已停止生成”；不显示积分、结算、余额或充值入口。
  - [ ] 发送前余额不足时不创建助手消息，保留可编辑草稿，禁用发送，并只在输入框上方显示“积分不足，暂时无法发送”和“去充值”。
  - [ ] 生成中余额耗尽时停止后续生成、保留部分输出，只在该回答末尾显示“积分不足，本次生成已停止”和“去充值”；输入区禁用但不重复横幅。
  - [ ] 充值后不自动发送、不自动续写，也不增加“继续生成”快捷按钮；用户在普通输入框中主动发起新请求。
  - [ ] 系统错误且无可用输出时不扣积分、不生成零消耗记录；有可用部分输出时只按返回部分计费。
  - [ ] 无法确认余额、对账或供应商状态时，发送前统一显示“服务暂时不可用，请稍后重试”，生成中统一显示“服务异常，本次生成已停止”；只提供“重试”，不显示“核对中”、供应商或充值入口。
  - [ ] 不向普通用户展示模型、Token 或供应商；Polo 助手调用 Skill 时，对外消耗记录仍统一记为“Polo 助手”。

### FR-009：本地 Web App 按实际用量计费

- **优先级**：P0
- **描述**：FDE 制作的 Web App 下载到本机运行，通过 Polo localhost API 使用 AI 算力；Polo 不承载 App 的任务输入、执行过程或结果页面，本轮统一按实际用量计费。
- **验收标准**：
  - [ ] App Catalog 或 App Index 显示“按实际用量计费”；不新增 Polo 报价确认页、执行结果页或系统报价弹窗。
  - [ ] 已安装 App 从 Catalog/Index 一次点击后直接启动并在 Polo App Tab 打开。
  - [ ] 首次安装只保留版本、下载大小和权限确认；确认后自动下载、安装、启动并打开，最多两次点击。
  - [ ] 未新增权限的更新不增加确认；新增权限时必须重新确认。
  - [ ] 一次用户可理解的任务对应一个 App Run；FDE App 创建 Run，内部多次 AI 调用携带同一 Run ID，完成或失败时结束，异常退出或长期未结束时由 Polo 超时收口。
  - [ ] 同一 App Run 的实际用量汇总扣费，并只形成一条以 App 名称展示的消耗记录。
  - [ ] AI 请求没有可用输出时不扣费；部分输出按实际返回部分计费。
  - [ ] AI 已正常返回后，FDE App 自身处理或最终交付失败仍按实际算力计费，不自动退款；争议补偿追加账本事实，不改写原记录。
  - [ ] App 调用因积分不足被拒绝时不产生消耗；Polo 在当前 App Tab 显示非模态平台提示，个人/Owner 可“去充值”，Manager/Member 只能“通知 Owner”。
  - [ ] 充值返回沿用用户点击后单次查询；到账后移除阻断但不自动重试 App 操作，用户在 App 内重新发起。
  - [ ] “从任务首页到发起并完成核心任务不超过 3 次关键点击”仅作为 FDE 产品建议，不属于本轮交付或验收要求。

### FR-010：按量计费规则和底层路由变化

- **优先级**：P0
- **描述**：计费公式和供应商路由可演进，但不能追溯改变已形成的 App Run 和账本事实。
- **验收标准**：
  - [ ] 新公式只影响生效后新创建的 App Run 或助手请求。
  - [ ] 已开始的 App Run 使用创建时冻结的计费规则版本。
  - [ ] 余额数量不因公式变化重新折算。
  - [ ] 明显涨价时在 Catalog/Index 或助手下一次发送前提示计费规则更新，不解释模型成本。
  - [ ] 同一种用户任务使用统一积分规则，底层供应商成本差异由 Polo 内部承担。

## 8. 支付订单与渠道

### FR-011：首发市场与支付方式

- **优先级**：P0
- **描述**：首版仅面向中国大陆，以人民币结算，支持微信 Native 和支付宝二维码。
- **验收标准**：
  - [ ] 微信和支付宝展示相同最终价格。
  - [ ] 支付通道手续费由 Polo 承担，不向用户加收。
  - [ ] Polo 是面向用户的销售、协议、发票、退款和消费者责任主体。
  - [ ] 算力供应商只与 Polo 发生 B2B 关系，不作为用户可见销售方。

### FR-012：桌面与移动端支付

- **优先级**：P0
- **描述**：桌面浏览器提供完整二维码支付；移动端首版仅查看和引导。
- **验收标准**：
  - [ ] 桌面端可创建、刷新、查询二维码订单。
  - [ ] 浏览器支付中心停留在二维码页时可轮询渠道事实；Polo 客户端不继承该轮询。
  - [ ] 移动端提示使用电脑或另一设备扫码。
  - [ ] 首版不提供微信 JSAPI、H5、支付宝 App 拉起或长按识别支付。

### FR-013：二维码和迟到支付

- **优先级**：P0
- **描述**：二维码有效期为 15 分钟。
- **验收标准**：
  - [ ] 页面显示倒计时。
  - [ ] 过期后先服务端查询并关闭旧订单，再按最新商品价格创建新订单。
  - [ ] 过期后的迟到付款不自动发积分或权益，进入人工核查并优先原路退款。

### FR-014：订单目标和幂等

- **优先级**：P0
- **描述**：订单创建时冻结目标 ProductSpace、商品、金额和渠道。
- **验收标准**：
  - [ ] 用户明确确认购买给“我的空间”或具体企业空间。
  - [ ] 支付成功后不得转移目标空间。
  - [ ] 同一 ProductSpace、商品和渠道同时最多一个待支付订单；刷新复用原订单。
  - [ ] 切换渠道前先查询或关闭原订单；未知状态阻止重复下单。
  - [ ] 两个合法订单都支付成功时，两笔均入账，不吞单。
  - [ ] 浏览器关闭后回调继续处理。
  - [ ] “我已支付”只触发服务端查询，不能由用户确认到账。
  - [ ] 深链只携带订单 ID，客户端重新查询服务端状态。
  - [ ] 从充值浏览器返回 Polo 客户端时弹出“是否已完成充值？”，只提供“已完成，查询结果”和“还没有”。
  - [ ] Polo 客户端不轮询充值结果；只在用户点击“已完成，查询结果”时查询服务端一次。
  - [ ] 查询结果为已到账时关闭弹窗并恢复发送；处理中显示“充值处理中”和“再次查询”；未查到付款时显示“暂未查询到充值结果”和“重新查询”。
  - [ ] 点击“还没有”只关闭弹窗并保留原积分不足提示；任何查询结果都不自动发送或续写。
  - [ ] 已支付但未发放时显示“处理中”并阻止重复购买。

### FR-015：代付

- **优先级**：P0
- **描述**：允许他人扫描订单二维码付款，但代付不形成产品权限。
- **验收标准**：
  - [ ] 价值归订单目标 ProductSpace。
  - [ ] 代付人不获得余额、订单、退款、发票或空间管理权限。
  - [ ] 订单详情仅显示渠道、金额、时间和脱敏付款标识。
  - [ ] 企业订单由个人代付时，积分仍为企业资产，发票可开给企业。
  - [ ] 退款仍回实际付款人的原渠道。

### FR-016：支付安全和订单风控

- **优先级**：P0
- **描述**：只有状态正常、完成手机号验证且 ProductSpace 已就绪的业务账号可购买。
- **验收标准**：
  - [ ] 工作人员账号、暂停账号和空间准备中账号不能创建订单。
  - [ ] 平台支持可配置的单笔和单日金额上限，具体值不写死在客户端。
  - [ ] 超限时不拆单规避，显示人工联系入口。
  - [ ] 单笔风险拒绝只阻止新购买，不自动冻结已有余额或任务。
  - [ ] 风控原因不向用户暴露具体规则。

## 9. 积分账本、供应商与对账

### FR-017：权威边界

- **优先级**：P0
- **描述**：Polo 与供应商分别维护互补权威事实。
- **验收标准**：
  - [ ] Polo 是人民币订单、积分发放、批次、退款和用户账单权威。
  - [ ] 供应商是实时算力执行、消耗回执和供应商限额权威。
  - [ ] Polo 保存任务、预占、供应商回执和对账镜像，不以本地缓存冒充供应商状态。

### FR-018：余额、预占与并发

- **优先级**：P0
- **描述**：一个 ProductSpace 在所有设备共享同一余额，通过原子预占防止超扣。
- **验收标准**：
  - [ ] 顶部当前空间区域不显示积分数字。
  - [ ] 点击头像展开菜单后，个人用户显示“可用积分 126.0900”类四位小数余额，Enterprise Owner 显示当前企业可用积分。
  - [ ] 个人用户和 Enterprise Owner 的积分数字在余额 `>= 100` 时使用默认文字色，`> 10` 且 `< 100` 时使用橙色，`<= 10` 时使用红色；不额外显示“余额较低”标签。
  - [ ] Enterprise Manager/Member 的头像菜单只显示“企业算力可用”或“企业算力不足”，不显示数字，不进入订单或财务详情。
  - [ ] 积分详情展示套餐、加油包、到期时间、可用积分和处理中预占积分。
  - [ ] 多设备并发任务不会重复使用同一积分。
  - [ ] 流水记录设备、操作者、任务和 ProductSpace。
  - [ ] 一台设备退出不取消其他设备任务或预占。

### FR-019：余额展示、消耗记录和对账差异

- **优先级**：P0
- **描述**：正常展示最近已对账余额；消耗记录只展示已经形成的正式积分变动。
- **验收标准**：
  - [ ] 任务结束到正式扣减之间不显示预计消耗或临时记录，不改写用户已看到的记录。
  - [ ] Polo 助手的正式记录使用用户发送请求的时间，固定格式为“`2026-08-20 14:32 · Polo 助手 · 消耗 2.4100 积分`”。
  - [ ] 独立 App 沿用同一格式并用 App 名称替换“Polo 助手”；助手调用 Skill 仍记为“Polo 助手”。
  - [ ] 单条消耗记录不可点击，不展开详情，不显示标题、余额、成员、“已结算”或常规状态标签。
  - [ ] 返还和纠错不改写或删除原消耗记录，另追加同格式的“`2026-08-20 16:05 · Polo 助手 · 返还 2.4100 积分`”。
  - [ ] 未发生扣减时不生成“消耗 0.0000 积分”记录。
  - [ ] 我的空间记录使用北京时间，企业空间使用该企业账单时区；时区只在页面统一说明，不追加到单条记录。
  - [ ] 消耗记录严格按 ProductSpace 分开，按时间倒序，只提供时间范围筛选和分页。
  - [ ] Enterprise Owner 可看企业消耗记录，但单条不显示操作成员；Manager/Member 不查看任何企业积分金额或消耗记录。
  - [ ] “消耗记录”页底部统一提供“账单有疑问”；用户按时间范围描述问题，不在单条记录上放申诉入口。
  - [ ] 出现差异时，支付中心可显示“核对中”并暂停该空间新的付费执行；Polo 助手只显示通用服务异常提示。
  - [ ] 供应商迟报超过预授权的部分不把用户余额扣成负数，由 Polo 承担并进入供应商异常；确认作弊时另走风控。

### FR-020：供应商不可用时的降级

- **优先级**：P0
- **描述**：无法确认余额或授权时采取保守策略。
- **验收标准**：
  - [ ] 不启动新任务。
  - [ ] 已完成授权的任务可在授权范围内结束。
  - [ ] 支付仅在积分发放队列可靠时继续开放；否则暂停新订单。
  - [ ] 渠道关闭时旧订单仍可查询、回调和退款，已有积分不受影响。

### FR-021：供应商凭证用户流程

- **优先级**：P1
- **描述**：供应商凭证必须按 ProductSpace 隔离。
- **验收标准**：
  - [ ] 个人空间和每个企业空间使用不同凭证范围。
  - [ ] 企业可采用一个企业主 Key 和成员独立子 Key，以支持共享余额和成员审计。
  - [ ] 充值到账后，因余额不足被限制的成员在下一次执行获取新凭证，不要求重新登录。
  - [ ] 成员在助手遇到企业积分不足或本月额度达上限时不看到充值入口，只能“通知 Owner”；发送成功后主动作变为“检查是否恢复”。
  - [ ] “通知 Owner”对同一限制事件幂等；Owner 通知只包含成员、企业、发生时间和“Polo 助手”，不包含对话标题、提示词、文件或回答内容。
  - [ ] 成员点击“检查是否恢复”时只查询一次；已恢复则移除提示并恢复发送，仍不自动重跑中断任务。
  - [ ] 中断任务不自动重跑；人工暂停的成员不因充值自动恢复。

Key 的层级、有效期、轮换、下发和刷新协议在后续技术方案中确定；客户端不得持有永久有效凭证。

## 10. 退款、拒付、申诉、补偿和发票

### FR-022：算力商品退款

- **优先级**：P0
- **描述**：退款按原始购买批次处理。
- **验收标准**：
  - [ ] 仅未使用、未预占、未过期的已购积分可退。
  - [ ] 按原批次购买单价退款；已消耗和已过期部分不退。
  - [ ] 用户从原订单发起，只能一次退回该订单当前全部可退部分，不输入任意数量。
  - [ ] 申请后冻结批次；退款成功后 30 天套餐立即结束，可重新购买。
  - [ ] 个人由本人操作；企业由当前 Owner 操作。
  - [ ] 原支付渠道退款给原付款人。

### FR-023：支付成功但发放失败

- **优先级**：P0
- **描述**：支付成功后进入积分发放流程，30 天有效期仍从 `paidAt` 开始。
- **验收标准**：
  - [ ] 发放中显示“处理中”，不允许重复购买同一受限商品。
  - [ ] 不因短期发放延迟顺延套餐到期时间。
  - [ ] 24 小时仍无法发放时自动全额原路退款、关闭订单，并不再补发积分。

### FR-024：金额不一致和原渠道不可退

- **优先级**：P0
- **描述**：渠道实付金额与订单金额不一致时不发积分或权益。
- **验收标准**：
  - [ ] 不按比例发放，不接受客户端改价。
  - [ ] 进入人工核查，完成原路退款或真实订单补款。
  - [ ] 原渠道注销或超过退款期限时，验证原付款人身份后人工退至其实名银行账户。
  - [ ] 不退款给当前使用者、企业当前 Owner，也不自动改回积分。

### FR-025：拒付和待偿金额

- **优先级**：P0
- **描述**：支付机构拒付时扣回未使用积分；已消耗价值形成目标 ProductSpace 的待偿金额。
- **验收标准**：
  - [ ] 原积分和消费流水不改写。
  - [ ] 待偿期间暂停该 ProductSpace 的新付费执行，补缴后恢复。
  - [ ] 他人代付后拒付，责任仍归获得价值的 ProductSpace。
  - [ ] 企业 Owner 转让不转移或抹除企业待偿责任。

### FR-026：任务计费申诉

- **优先级**：P1
- **描述**：用户可按任务发起一条有效计费申诉。
- **验收标准**：
  - [ ] 不自动退款或修改原扣费。
  - [ ] 平台对比 Polo 与供应商事实；成立后追加补偿或返还流水。
  - [ ] 平台默认不读取对话、文件和 App 输入输出；用户可主动附加材料。
  - [ ] 主观不满意不自动退款。

### FR-027：服务补偿积分

- **优先级**：P1
- **描述**：失败释放与额外补偿是不同操作。
- **验收标准**：
  - [ ] 失败任务释放的积分回到原批次并保留原到期时间。
  - [ ] Polo 额外赠送的服务补偿积分单独记账，30 天有效、不可退款、不可转让并优先消耗。

### FR-028：发票

- **优先级**：P1
- **描述**：发票依据人民币订单开具，不依据积分消耗。
- **验收标准**：
  - [ ] 个人和企业均可申请；企业仅 Owner 操作。
  - [ ] 已退款订单不能重复开票；已开票后退款需要红冲。
  - [ ] 首版允许人工电子发票流程，但必须有可追踪状态。
  - [ ] 企业订单由个人代付时仍可按企业订单开具企业发票。

## 11. 企业预算与生命周期

### FR-029：企业共享余额和月度总预算

- **优先级**：P1
- **描述**：企业成员共享一个企业 ProductSpace 积分账户；Owner 可选择设置企业自然月总预算上限。
- **验收标准**：
  - [ ] 企业月度总预算默认是否开启由后续 UI/运营配置明确，但只有 Owner 可修改。
  - [ ] 按企业账单时区和自然月统计；新月份只重置用量，不重置余额。
  - [ ] 达到上限后即使余额充足也不启动新任务；已预授权任务可完成。
  - [ ] 企业本月额度达上限时，Owner 在 Polo 助手看到“企业本月算力额度已达上限，暂时无法发送”和“调整预算”；Manager/Member 看到同一原因和“通知 Owner”。
  - [ ] 预算达上限与积分不足使用不同文案和恢复动作；充值不能伪装成解除预算上限。
  - [ ] Owner 调低上限时不能低于当月已用加已预占。
  - [ ] 达到预算上限后仍可充值，但购买页提示“充值不会解除本月用量上限”。
  - [ ] 不实现个人月度上限、企业成员限额或成员组限额。

### FR-030：Owner 转让

- **优先级**：P1
- **描述**：企业所有权转让不改变企业资产和历史责任。
- **验收标准**：
  - [ ] 未支付订单自动关闭；已支付且发放中的订单继续处理。
  - [ ] 余额、历史和待偿金额留在企业。
  - [ ] 新 Owner 获得财务权限，原 Owner 立即失去写权限。
  - [ ] 退款仍回原付款渠道；已开始任务继续完成。

### FR-031：企业关闭

- **优先级**：P1
- **描述**：企业关闭前必须核清多付款人、多批次和财务责任。
- **验收标准**：
  - [ ] 各购买批次分别退回原付款人和原渠道，不能把全部余额付给当前 Owner。
  - [ ] 余额、退款、发票、拒付、待偿和争议均处理完成后才可关闭。
  - [ ] 关闭中禁止新购买和新执行，保留 Owner 必要的账单、退款、发票和导出能力。

## 12. 圈子订阅与内容权益

### FR-032：圈子订阅归属

- **优先级**：P1（增量 B）
- **描述**：圈子只面向个人空间，一个个人空间可同时订阅多个圈子。
- **验收标准**：
  - [ ] 每个圈子同一时间只采用免费、仅邀请或付费订阅中的一种主要加入模式。
  - [ ] 加入入口继续来自邀请链接、二维码或创作者分享；当前版本不建设公开圈子市场。
  - [ ] 企业空间不能创建、持有、续费或接收圈子订阅订单。
  - [ ] 订阅权益绑定目标 personal ProductSpace，不能转给另一个人或企业。
  - [ ] 圈内 App/Skill 只进入该个人空间，并只扣该空间积分。
  - [ ] 各圈子的订阅、续费、到期、退款和撤权互不影响。
  - [ ] 所有圈子 App 共用个人空间积分，不建立圈子独立积分池；流水保存圈子和 App 的内部关联。

### FR-033：圈子订阅周期和续费

- **优先级**：P1（增量 B）
- **描述**：一个圈子首版只有一个 30 天订阅价格，完全手动续费。
- **验收标准**：
  - [ ] 周期从支付成功时刻起算 30 天，不按自然月。
  - [ ] 允许提前续费并从当前到期时刻顺延，最多累计 12 个月。
  - [ ] 无自动续费、取消自动续费和自动续费失败宽限期。
  - [ ] 到期前创建且在二维码有效期内支付成功的续费订单，从原到期时刻顺延，视为连续订阅。
  - [ ] 仅提供到期提醒和“立即续费”。
  - [ ] 首版无年度套餐、会员多档、免费试用、优惠券或限时折扣。

### FR-034：圈子加入模式变化

- **优先级**：P1（增量 B）
- **描述**：圈子仍可选择免费、仅邀请或付费订阅模式，但模式变化不能静默收费或吞掉权益。
- **验收标准**：
  - [ ] 免费/邀请制改付费时，现有成员收到通知并获得 30 天过渡期，必须主动购买；未购买者过渡期结束后失效。
  - [ ] 付费改免费时停止新付费订单，现有已付周期继续，到期后自动转为免费成员，不自动退款。
  - [ ] 创作者赠送免费资格不覆盖或退款已有付费周期，赠送期限从已付周期结束后顺延。

### FR-035：创作者定价

- **优先级**：P1（增量 B）
- **描述**：创作者自行设置圈子 30 天订阅价格，但平台保留价格边界和审核。
- **验收标准**：
  - [ ] 价格必须位于平台配置的最低价和最高价之间。
  - [ ] 首次定价和后续调价需要平台审核。
  - [ ] 调价不影响当前已付周期；下一次续费展示新价格并由用户重新确认。
  - [ ] 创作者不能自行设置积分、算力或单个 App/Skill 价格。

### FR-036：圈子内容权益到期和退款

- **优先级**：P1（增量 B）
- **描述**：订阅到期、退款、退出或圈子停止服务时撤销对应圈子后续使用权。
- **验收标准**：
  - [ ] 到期后不能查看付费内容或启动圈内 App/Skill。
  - [ ] 到期前已预授权的任务可以完成。
  - [ ] 已经合法下载到本地或保存到个人空间的结果不追溯删除。
  - [ ] 退款成功立即撤销该圈子权限，不影响其他圈子、Polo 助手或个人积分。
  - [ ] 不提供按剩余天数自助退款；重复扣款、系统故障或停服可退款，其他情况人工审核。
  - [ ] 主观不满意不自动退款。

### FR-037：圈子调价、停服和关闭

- **优先级**：P1（增量 B）
- **描述**：圈子停服不能立即吞掉已付权益。
- **验收标准**：
  - [ ] 被封禁或主动停止服务时立即停止新订阅。
  - [ ] 创作者主动关闭时先进入停止运营状态，可服务到全部订阅期结束，或按未履约部分退款后提前关闭。
  - [ ] 订阅期内允许正常更新内容，但不能无替代地移除核心购买权益；重大缩水进入申诉和人工退款。
  - [ ] 不为每个订阅者永久冻结一份旧内容快照。

### FR-038：创作者和圈子责任

- **优先级**：P1（增量 B）
- **描述**：创作者及圈子管理员通过角色获得管理访问，不能自买自卖。
- **验收标准**：
  - [ ] 创作者和授权管理员不能购买自己管理的圈子订阅。
  - [ ] 圈子所有权转让需要平台审核，现有订阅继续有效。
  - [ ] 转让前订单收入归原创作者，转让后订单收入归新创作者，以支付时间划分。
  - [ ] 外部支付机构确认拒付后暂停对应订阅并冻结或冲减创作者待结算收入，订单保留独立争议状态。

## 13. 创作者收入与结算

### FR-039：内容收入与算力收入分离

- **优先级**：P1（增量 B）
- **描述**：创作者只参与圈子内容订阅收入，不参与积分购买或算力消耗收入。
- **验收标准**：
  - [ ] 用户实付减退款作为创作者分成计算基数。
  - [ ] 分成规则在订单支付时快照保存。
  - [ ] 微信/支付宝通道手续费由 Polo 承担，不从创作者收入二次扣除。
  - [ ] 税费按创作者主体类型依法处理，不在产品中承诺统一税后金额。

### FR-040：创作者准入和结算

- **优先级**：P1（增量 B）
- **描述**：只有完成身份、协议和收款资料的创作者可开启付费订阅。
- **验收标准**：
  - [ ] 完成实名认证、绑定收款账户并签署平台协议。
  - [ ] 收入先进入待结算，经过 30 天退款/拒付风险期后转为可结算。
  - [ ] 每月结算一次，达到 100 元才付款；不足自动累计，不收提现手续费。
  - [ ] 首版允许人工打款，但状态和结算单可追踪。

### FR-041：收款账户和负结算余额

- **优先级**：P1（增量 B）
- **描述**：收款账户变更和负余额需要防盗与追偿机制。
- **验收标准**：
  - [ ] 修改收款账户需重新验证身份并等待 7 天，同时通知原、新联系方式。
  - [ ] 等待期内款项留在平台，历史结算不改变。
  - [ ] 退款或拒付导致负数时暂停付款，并从后续内容收入抵扣。
  - [ ] 关闭账号仍有负数时依据平台协议人工追偿，不改写历史结算单。

### FR-042：退款责任归属

- **优先级**：P1（增量 B）
- **描述**：退款由导致未履约的一方承担。
- **验收标准**：
  - [ ] Polo 支付或平台系统故障造成的退款/补偿由 Polo 承担，不扣创作者收入。
  - [ ] 创作者停服、违规移除核心内容或无法履约造成的退款，从待结算或后续收入扣除。
  - [ ] 正常服务下的主观不满意不自动退款。

## 14. 账号、空间和渠道生命周期

### FR-043：个人账号暂停和注销

- **优先级**：P1
- **描述**：暂停或注销中禁止新购买和新执行，但保留财务善后。
- **验收标准**：
  - [ ] 可只读查看余额、订单、退款、发票和争议。
  - [ ] 注销前退回全部符合条件的已购积分。
  - [ ] 试用、补偿和已过期积分不可兑现金，用户明确确认后失效。
  - [ ] 资金和积分未处理完成前不能正式注销。
  - [ ] 法定保留的交易和审计记录不随业务内容删除。

### FR-044：渠道停用

- **优先级**：P0
- **描述**：单一支付渠道临时关闭只影响新订单。
- **验收标准**：
  - [ ] 停止该渠道新订单。
  - [ ] 旧订单继续查询、回调、退款和人工处理。
  - [ ] 已有积分和订阅权益不受影响。

## 15. 页面、入口与状态清单

下一阶段先依据本节绘制用户流程，再制作高保真 UI。不得跳过状态设计。

### 15.1 Polo 客户端

- 顶部当前空间区域：不显示积分数字或财务状态。
- 头像菜单：个人和 Enterprise Owner 显示当前空间四位小数可用积分与“积分与订单”入口，并按 `100`、`10` 两档阈值改变数字颜色；Manager/Member 只显示企业算力状态，不显示金额或财务入口。
- Polo 助手正常态：不显示保护上限、积分、余额、实际消耗或“已结算”；主动中止只显示“已停止生成”。
- Polo 助手余额不足：发送前只在输入区提示，生成中只在部分回答末尾提示；每个页面只有一个恢复入口。
- Polo 助手企业角色：Owner 可“去充值”或“调整预算”；Manager/Member 只能“通知 Owner”和“检查是否恢复”。
- App Catalog/Index：统一展示“按实际用量计费”；已安装一键直接打开，首次安装确认版本、大小和权限后自动安装、启动并打开。
- 本地 App Tab：不增加 Polo 任务、报价或结果中转页；积分不足时只叠加非模态平台提示，并按角色提供“去充值”或“通知 Owner”。
- 余额不足恢复：充值入口打开当前 ProductSpace 的“算力商品”页，不自动选商品或创建订单；返回客户端后由弹窗按钮触发单次查询，不轮询、不自动发送。
- 我的圈子：圈子列表、订阅状态、到期时间、手动续费、退出、退款处理中。
- 空间切换：只含“我的空间”和企业空间，不含圈子；切换后重新加载余额、目录、权限和执行上下文。

### 15.2 浏览器支付中心

- 算力商品页：试用、30 天套餐、三档加油包、个人/企业目标确认。
- 订单支付页：微信/支付宝、二维码、15 分钟倒计时、轮询、“我已支付”查询。
- 订单结果：待支付、状态未知、已支付待发放、成功、已过期、已关闭、迟到支付核查、金额不符。
- 积分 -> 余额：可用总数、套餐/加油包批次、预占、最近到期、核对中。
- 积分 -> 消耗记录：每次正式消耗或返还一行，不可点击；固定显示时间、“Polo 助手”或 App 名称、四位小数积分变动，只提供时间筛选、分页和页底“账单有疑问”。
- 退款与发票：可退金额、冻结中、退款中、已退款、原渠道不可退、开票中、已开票、红冲中。
- 账号受限：暂停/注销善后、大额限制、风控拒绝、渠道不可用。

### 15.3 企业管理端

- Owner 财务总览：余额、预占、套餐、订单、成员汇总、自然月预算和用量。
- 企业充值、退款、发票、导出。
- 月度预算达到、调整、调低冲突和“充值不会解除上限”提示。
- Owner 转让、企业 closing、原付款人退款和财务责任清单。
- Manager/Member 不出现企业总余额、订单和充值入口。

### 15.4 创作者工作台

- 圈子付费开通准入状态；
- 圈子价格和调价审核；
- 免费/邀请/付费模式变化；
- 成员订阅、赠送资格、到期、暂停和退款处理中；
- 收入总览：实付、退款、拒付、待结算、可结算、已结算、负余额；
- 收款账户和 7 天等待期；
- 停服、关闭、所有权转让和成员善后。

### 15.5 平台运营端

- 支付/发放/回调/退款/拒付/发票异常队列；
- 积分与供应商对账差异；
- 迟到支付、金额不符、原渠道不可退；
- 任务计费申诉和服务补偿；
- 创作者定价审核、结算、负余额和退款归责；
- 圈子关闭、企业关闭和账号注销财务核清。

### 15.6 通知

- 积分到期前 7 天、3 天和 1 天各提醒一次；批次已用完则不提醒。
- 同一业务通知跨设备只生成一条。
- 低余额在头像菜单仅以积分数字颜色表达（不足 `100` 为橙色，`10` 以内为红色），不显示“余额较低”标签；通知中心只发送一次，不进入 Polo 助手对话。
- 余额不足、预算达到、价格变化、订阅到期、退款/拒付和收款账户变化均需要状态通知。
- 企业成员的余额不足/预算达到通知只发给唯一 Owner，不包含对话、文件或回答内容。
- 不自动充值、不自动续费、不自动重跑中断任务。

## 16. 核心状态与异常处理

| 对象/场景 | 处理策略 |
|---|---|
| 支付状态未知 | 保持处理中，只允许服务端查询，不重复下单或发权益 |
| 二维码过期 | 查询并关闭旧订单，重新确认最新价格后新建订单 |
| 迟到支付 | 不自动发放，人工核查并优先退款 |
| 支付金额不符 | 不发放、不按比例折算，人工核查 |
| 已支付待发放 | 显示处理中，阻止受限商品重复购买 |
| 24 小时未发放 | 自动全额原路退款并关闭，不再补发 |
| 回调重复/乱序 | 以订单状态机和幂等键收敛，不重复发放、退款或结算 |
| 多设备并发执行 | 原子预占；一个积分不能被两个任务同时使用 |
| App Run 执行期间积分到期 | 已授权范围内可完成；需要扩展授权但积分不足时停止后续 AI 调用，已有输出按实际用量计费 |
| 助手发送前余额不足 | 不创建助手消息，保留可编辑草稿；只在输入区显示一次余额不足与恢复动作 |
| 助手生成中余额耗尽 | 停止、保留部分输出、按实际扣费；只在部分回答末尾显示一次余额不足，充值后由用户发起新请求 |
| 助手主动中止 | 保留部分输出，只显示“已停止生成”，不显示计费或充值信息 |
| App AI 请求失败 | 无可用输出不扣费；部分输出按实际部分计费 |
| FDE App 后处理失败 | AI 已正常返回时仍按实际算力计费；不自动退款，争议补偿追加账本事实 |
| 余额/消耗不可确认 | 不启动新任务；已授权任务在范围内完成 |
| 对账差异 | 支付中心显示核对中，暂停新付费执行，追加修正流水；Polo 助手只显示通用服务异常 |
| 支付拒付 | 扣回剩余价值，已消费部分形成空间待偿金额 |
| 退款成功但权益更新失败 | 进入可恢复异常队列，不伪装整体成功 |
| 圈子订阅到期 | 撤销该圈子新启动权，其他圈子和个人积分不受影响 |
| 圈子停服 | 停止新订阅；服务到期或按未履约部分退款 |
| 企业 Owner 转让 | 企业资产与责任不动，仅财务操作人切换 |
| 账号/企业关闭 | 先核清余额、退款、发票、拒付、争议和责任，再正式关闭 |

## 18. 非功能性要求

### 18.1 一致性和幂等

- 资金、积分、权益和结算动作必须使用业务幂等键。
- 原始订单、原始支付事实和历史流水不可修改或删除；纠错使用反向或补充记录。
- 支付回调、主动查询、浏览器轮询和人工处理可并发，但最终只能产生一次业务效果。
- ProductSpace、圈子、订单、作品和供应商执行标识不能通过名称或客户端参数推断。

### 18.2 安全和隐私

- 服务端每次重新验证账号、ProductSpace、企业角色和圈子权益。
- 支付、退款、发票、收款账户、预算和平台资金调整记录不可变审计。
- 客户端、日志和深链不携带完整付款人信息、渠道密钥或永久供应商 Key。
- 创作者和平台工作人员默认不能查看用户对话、文件、App 输入输出。
- 风控失败不暴露规则细节。

### 18.3 可用性和降级

- 不能确认授权、余额或供应商状态时 fail closed。
- 查询、退款和财务善后能力不能因停止新销售而同时关闭。
- 真实通道默认关闭，CI 和验收使用可控假 Provider；生产开放必须显式配置。

### 18.4 可观察性

- 每个订单、回调、发放、预占、供应商执行、退款和结算可通过稳定 ID 串联。
- 对账差异、迟到支付、权益更新失败和结算失败进入可领取、可恢复的运营事件。
- 运营指标不得默认包含用户业务内容。

### 18.5 性能与容量

本阶段未锁定 QPS、余额查询延迟或结算数据规模。下一阶段必须基于供应商接口 SLA、预计付费用户数、任务并发和回调峰值补齐容量指标；在此之前不得虚构数值。

| `User.monthlyQuotaTokens`、`QuotaPeriod`、`UsageRecord` | 用户级 Token 月配额 | 不能冒充 ProductSpace 积分钱包或企业预算；个人不做月度上限，企业另建可选总预算 |
| 旧企业用量描述 | Manager 可查看较多企业用量或聚合 | 第二轮支付首版中 Manager 与 Member 相同：只看企业算力状态，不看积分金额、消耗记录或任何企业财务详情 |
| 第二轮 Polo 客户端支付原型 | 对话输入区显示单轮保护上限，回答显示“已结算”、实际消耗、剩余积分和复杂中断卡片 | 从 Polo 助手对话移除全部积分与结算信息；只保留一次轻量余额不足提示，正式消耗转移至支付中心“消耗记录” |
| 第二轮 Polo 客户端 App 原型 | Polo 承载固定报价确认、报价过期、执行结果和计费申诉页面 | App 是 FDE 制作并在 localhost 运行的独立 Web App；删除全部 Polo 中转页，本轮只做按实际用量计费、直接启动和平台级积分不足恢复 |
| 早期支付任务描述 | 永久预付积分为唯一商品 | 第二轮完整商品为 7 天试用、一款 30 天套餐、三款永久加油包；现有 POL-94 首轮边界不被本文件直接改写 |
| 早期圈子归属表达 | CircleMembership 更接近账号关系 | 付费订阅和内容权益必须落到该账号唯一的 personal ProductSpace，企业空间不得持有 |

这些变更应通过第二轮需求/ADR/UI 专项更新完成，不能在现有 `implementation-orchestration-plan` 中悄悄改词造成第一轮任务漂移。

## 20. 权衡与决策记录

| 决策点 | 已选择 | 原因 | 未选择方案 |
|---|---|---|---|
| 积分用途 | 只支付算力 | 让内容价值、算力成本和退款责任清晰 | 积分同时买圈子/App/Skill |
| 模型可见性 | 面向任务，不展示模型 | 避免用户把注意力放在模型品牌而非任务完成 | 公开模型和 Token 单价 |
| 自由对话计费 | 实际消耗 + 平台内部单轮保护上限 | 无法可靠预估总消耗，但不应把计费负担带入对话 | 在对话中显示上限、实际消耗、余额或结算状态；固定价或按结果付费 |
| Polo 助手消耗展示 | 只在支付中心“消耗记录”显示正式变动 | 保持对话专注，同时保留可对账的财务事实 | 在每条助手回答后显示消耗和剩余积分 |
| 当前 App 计费 | App 级统一按实际用量计费，按用户任务归集 App Run | 符合 FDE 本地 App 的真实运行边界，避免 Polo 复制任务页面 | 当前实现固定报价或依赖 FDE 统一计费 UI |
| 固定 App 计费 | 整体延期，排期未定；未来在 Catalog/Index 预披露且不增加运行时中转页 | 当前缺少稳定价格与 FDE 展示契约 | 本轮先实现固定报价确认和结果页 |
| 套餐命名 | 30 天算力套餐 | 当前没有会员权益 | Polo 会员 |
| 套餐价值 | 低单位价、30 天有效 | 与永久加油包形成合理选择 | 同价但更短有效期 |
| 自动续费 | 全部手动 | 当前无法满足委托代扣条件 | 自动扣款和宽限期 |
| ProductSpace | 资金/内容/执行强隔离 | 明确谁拥有数据、权益和费用 | 账号级混合余额 |
| 圈子与企业 | 圈子只进个人，企业只进企业 | 创作者面向个人，企业面向员工 | 企业订阅圈子或支付圈内算力 |
| 多圈子 | 一个个人空间可订阅多个 | 个人需求多样 | 一个空间只订阅一个圈子 |
| 作品跨圈 | 禁止同一作品跨圈分发 | 保持作品和圈子生命周期简单 | 一个作品多圈分发 |
| 企业预算 | Owner 可选总月度上限 | 防止共享余额被集中消耗 | 个人/成员/组多层配额 |
| 资金记录 | 追加式不可变账本 | 可审计、可对账、可恢复 | 直接编辑余额和订单 |
| 上线方式 | 算力支付先行，圈子支付后续 | 降低两套账本同时上线风险 | 一次性大爆炸交付 |
