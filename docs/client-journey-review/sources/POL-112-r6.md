# 第一站：共享身份、登录与端边界访谈

## Intent

先把“谁、从哪里、以什么身份、进入哪个端、看到什么、离开后怎样回来”讲清楚，使后续四端访谈消费同一套边界。不要直接把四端等同于四套账号，也不要默认需要统一登录。

## 已有规则与需验证的落差

- POL-68 的企业/创作者流程规定：仅从 Polo 客户端账号菜单进入浏览器；企业 Owner/Manager 可进入企业管理端；创作者是普通账号的资格，资格暂停/撤销保留责任处理只读入口；两个管理端无互跳且退出后重新登录。
- 平台运营使用独立工作人员账号，不从普通客户端进入；业务身份与平台身份分离。POL-88 已将这些要求写入入口/session 拆分范围。
- Admin 集成首页却展示三入口并说明独立会话。需要核实它是内部导航页、公开落地页还是临时调试页；首页展示、受控入口、合法深链和禁止直接进入分别适用于谁。

## Agent 先做的事实工作

对照文档、POL-77/POL-88/POL-90、相关认证页面/会话检查及客户端账号菜单；制作“身份 × 准入资格 × 入口 × 会话 × 登录后落点 × 拒绝/恢复 × 数据/付款上下文”表。区分业务账号、企业内角色、创作者资格、工作人员账号、ProductSpace；任何合并/简化均先标成建议。

核实首个工作人员账号如何开通、后续员工授权/撤权、最后一个有效管理员保护；Polo 账号注册/找回、创作者申请、首次创建企业与未具备资格时去哪里。现有证据无法回答的标为缺口，不擅自确定认证方式。

## 在本卡启动访谈的例子

1. 小李是企业 Owner，也是创作者：从桌面端进入企业管理后想发布作品，应看到什么、是否要退出、再次登录是否丢失原页面？
2. 普通成员误点 Platform admin login，或打开企业管理深链：该看到拒绝、登录还是引导，怎样回到可用入口？
3. 新运营员工第一次值班：谁给他账号、从哪里进入、账号过期或撤权后怎样交接未完成事项？

推荐先继承“工作人员与业务身份分离、权限由服务端判断”，优先裁定入口用途、说明、首登与恢复。是否改企业/创作者间切换是新的产品决定；明确会话独立不自动回答用户是否必须手动退出。给出实例和影响后由 owner 决定，不在本次建卡时更改旧规则。

- **继承**：普通业务账号可以同时拥有多家企业的不同角色和创作者资格；工作人员使用独立账号。ProductSpace 是消费、数据和付款上下文，不是另一套登录身份。
