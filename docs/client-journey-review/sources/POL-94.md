## A-0：App Metering Contract 冻结

冻结以下跨端字段与语义：

- 一次用户可理解任务对应一个 App Run；Run 绑定不可变 ProductSpace、付款主体、App、版本与计费规则快照。
- 同一 Run 内部多次 AI 调用共享 Run ID，服务端按实际用量聚合；无可用输出不扣费，部分输出按实际返回部分计费。
- AI 正常返回后 FDE 后处理失败仍按实际用量结算；补偿使用追加事实，不改写原消耗。
- 执行前积分不足 fail closed；超时、重复结束、迟到回执、幂等重放和异常释放按冻结合同确定性处理。
- 充值完成后的客户端恢复只允许用户点击后单次查询，不轮询、不自动发送、不自动续写、不自动重试。

## D-1：最终跨端验收与生产开放门禁

D-1 必须等待 POL-102、POL-103、POL-104、POO-47 和 POO-49 全部完成；POO-49 自身必须绑定已完成的 POO-48。

最终验收覆盖：

- Catalog 到 App Run、同 Run 多次内部调用归集、无/部分输出、正常返回后的后处理失败、Run 超时与并发结算。
- 个人/企业角色矩阵、跨空间 fail closed、支付商品、微信/支付宝二维码、重复/迟到回调、主动查询、退款和对账差异。
- 支付中心四位小数消耗记录与追加修正。
- App Runtime 平台级阻断、助手发送前不足、生成中耗尽、部分输出保留及充值后用户单次查询。
- 1440×900、1024×768、390×844 三视口的冻结原型 parity 证据。
- 真实商户配置、回调验签、对账、监控、灰度与回滚门槛。

在全部证据通过前，真实支付渠道保持默认关闭，不开放生产收款。

## 非目标

- 本卡不实现 App Run 服务端计量、支付订单、支付渠道、消耗记录页面、Catalog、Runtime、助手会话隔离或积分不足 UI。
- 不引入 App 固定报价、操作级固定价格、自动查询、自动发送、自动续写或自动重试。
- 圈子订阅、创作者收入与结算继续归 POL-91，和 ProductSpace 积分账户分账。

## 验收标准

1. A-0 合同字段、状态与异常语义在 POL-102、POL-103、POL-104、POO-47、POO-48、POO-49 中一致且无重复所有权。
2. D-1 的服务端、支付、权限、对账、客户端与三视口视觉证据全部绑定各子任务最终 HEAD。
3. 充值只解除阻断，不自动发送、续写、创建 Run 或重试 App。
4. 无真实扣减不生成消耗记录；修正只追加，账本、Run 和支付事实可对账。
5. 真实渠道只有在生产配置、验签、对账、监控、灰度和回滚门槛全部通过后才可显式启用。

子任务内部实现由各卡自行决策。只有 A-0 合同、商品/退款责任、真实商户权限或跨端产品边界需要改变时暂停裁决。
