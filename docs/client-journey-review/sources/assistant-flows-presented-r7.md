# Polo 助手：用户流程与场景（文字走查版）

对应 J-PC-04 / M05、M06、M08，引用已确认完整功能方案 D-PC-04 和 App 责任边界 D-PC-05。本文先讲用户怎么使用，不要求阅读原型，不新增功能决定或视觉确认。

## 先分清本轮看什么

- **直接沿用：**已有的助手对话、发送附件、Skills 等能力。用户已明确这些功能已经实现，本轮不把它们当成新需求重新设计。
- **本轮核对：**这些能力在个人/企业空间中的归属、权限变化、失败和重开后能否连成完整旅程。
- **实现状态：**以下描述来自已确认产品规则。具体哪个细节已经实现、哪个只缺验证，要对照源码和真实界面才下结论，不能因为画了线框就认定缺功能。本文不是已完成实现差异审计。
- V2 线框仅作此前的交互示例，不能默认替换已有助手界面。本轮先按以下文字找真正的差异，再决定是否需要看页面。

## 场景一：小王用企业助手整理客户材料

**角色与前提：**小王是启明设计的有效成员，已进入该企业空间，当前允许发起本次计算。

1. 小王从首页打开 Polo 助手。看到的是当前企业里自己有权访问的对话；第一次没有对话，就新建一条。
2. 他在对话里选择客户需求文件，输入“帮我整理需求，列出待确认事项”。发送前可以修改输入或重新选择材料。
3. 小王点击发送。助手处理当前空间允许访问的材料，并按需要使用当前空间已启用且仍有权限的 Skills。
4. 助手直接给出结果，或因缺少信息先向小王追问。不是每次都必须追问。
5. 消息、实际保存的附件和生成文件留在这条企业对话里。小王下次从企业助手打开原对话查看。

**成功结果：**小王取得回复，并知道以后回哪里找已保存的内容。

**直接沿用：**已有发消息、附件和对话能力；不是每次都要管理 Skill 或等待首次准备。

**核对重点：**企业对话不会混入个人历史；材料和 Skill 不能越过当前空间权限；已保存文件可从原对话访问。

## 场景二：这次工作需要一个尚未启用的 Skill

1. 小王从助手内部进入 Skills，找到企业提供的“需求整理”，辨认来源、版本和可用状态。
2. 企业允许他使用，不等于已经替他启用；小王明确启用后，才允许当前空间助手按任务需要使用。
3. 若本机需要准备资源，客户端完成准备；已经准备好的设备直接使用，不要求重复准备。
4. 小王回对话发送任务。以后不想使用时，可以停用；后续不再因为曾经启用过就调用。

**核对重点：**使用资格、本人启用、本机准备是不同事实。启用选择属于本人及当前空间，在本人设备间同步，不替同事启用，也不把个人 Skill 带进企业。

**失败恢复：**设备准备失败可以重试，不误报为授权取消；企业撤销资格则拒绝启用/调用，不能借旧缓存继续用。普通提问不以启用某个 Skill 为前置。

## 场景三：助手需要小王补充信息

例如助手问：“这份摘要给内部项目组看，还是给客户看？”

- 小王回答后，原对话只出现一条可读答案，助手继续原任务。
- 小王暂不回答，助手停在等待状态，不自动编一个答案继续。
- 回答提交时断网、结果未知，先核对原问题有没有收到答案；已收到就显示真实状态，不能盲目再发一遍。
- 另一设备已经回答，显示实际状态，不把本设备草稿再提交一次。
- 客户端重开后，验证账号、空间和原会话，再恢复该提问功能已有的问题状态及已保存回答草稿；不会自动提交。
- 原问题失效或原会话无权，不把答案转到其他对话。

**核对重点：**等待、已回答、未确定是否提交三种状态清楚，恢复不重复发消息。这里不新增“所有未发送草稿都保证恢复”的承诺。

## 场景四：生成到一半，用户停止、断网或积分不足

| 小王遇到什么 | 应看到什么 | 怎么继续 |
| --- | --- | --- |
| 主动点停止 | 已停止，保留实际产生并保存的内容 | 由小王决定下一次发送，不自动续写 |
| 网络或服务失败 | 未完成及真实原因；有部分回复就保留部分，不写成成功 | 恢复后重验状态，由小王明确决定下一次执行 |
| 发送前积分不足 | 原输入保留，本次发送被阻断，不创建新的助手消息 | 按角色处理余额/通知 Owner；完整流程见 J-PC-03 |
| 生成中积分不足 | 显示阻断原因，保留实际部分输出 | 处理后用户主动单次查询，再决定是否重新执行；不自动续写 |

**核对重点：**停止、网络失败、积分不足不能统称一种错误；网络恢复或浏览器付款成功不触发自动重发。具体恢复操作入口沿已有界面核对，不由线框强制新增一种“写新消息”方式。

## 场景五：第二天回来找结果或文件

1. 小王打开 Polo，重新核验登录和空间资格。
2. 进入原企业的助手，从对话列表找到“客户需求整理”。
3. 打开已保存的消息及文件，不重新执行昨天的任务。
4. 文件不存在时明确提示找不到；可以重新选择自己持有的文件，但不能声称已恢复原文件。

**核对重点：**助手自己的文件在原对话里找，不新增独立文件汇总页；失去企业权限不能通过旧附件链接继续访问。

**责任区别：**FDE App 的内容保存和历史由 App 自己负责；这里讨论的是 Polo 自有助手，因此 Polo 仍需负责自己的已保存消息、附件与访问控制。

## 场景六：工作中换空间或失去访问权（与其他旅程交接）

- 小王从企业切到“我的空间”：按 J-PC-02 先终止当前空间全部活动，成功后再整体切换。个人助手只展示个人内容，不搬企业对话、附件或问题；旧执行费用仍归原空间。
- 停止失败或目标加载失败：不能出现两空间数据混合，已停止的任务也不自动复活。
- 登录过期：重新认证后验证原空间和会话，恢复合法已保存内容，不自动发送。
- 企业将小王移除：立即阻止无权操作，停止相关活动，按 J-PC-06 返回有权个人空间或安全受限入口，不能用重登录绕过撤权。

这些只是当前故事的交接，运行中切空间及全部撤权恢复仍在对应旅程单独走查。

## 本条如何收口

正常对话、附件、Skills 如果现有交互已经满足上述规则，就直接沿用。只有发现具体不一致，才列“现状 → 用户卡在哪里 → 推荐调整 → 影响”，请用户判断真正的产品变化；未验证的地方列证据缺口，不当作缺功能。

本条尚未展开：Sources、Automations、Browser 和高级工具配置；Skill 同名多来源/版本深链及跨设备全过程；助手允许的跨空间文件导出/导入。其余客户端模块继续见完整功能方案与剩余清单。
