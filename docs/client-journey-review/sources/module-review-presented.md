# Polo 客户端完整功能方案审阅

这份文档把 11 个模块放在一起：每个模块都说明用户能做什么、从哪里进入、具体操作和结果、常见失败恢复、本轮范围及实现缺口。可直接从功能地图找到要看的模块，不需要先读 Spec，也不再逐模块等待对话。

**已确认，直接沿用：**

- 首页保留固定 Polo 助手和最多 5 个常用 App。用户没配置常用时，引导“全部 Apps”，不自动替用户挑选。
- App 自己负责业务内容、保存、历史和找回。Polo 提供容器和有权应用列表，不判断“是否保存到 Polo”。
- 独立文件汇总页延后；助手的附件和生成文件仍在原对话里。面向创作者的新 SDK/API 留待后续。
- 空间切换先终止全部活动；充值返回由用户单次查询，不自动发送、续写或重试。

**阅读标记：**“已有”来自已盘点的本地源码或局部验收，不等于当前线上完整可用；“待补”包括已设计未实现、未集成或尚无完整验收证据。本文是方案审阅材料，整理/阅读不代表整版 Spec 已接受。本轮不编码。

## M01 登录与进入空间


画布沿用 J-PC-01“首次：无邀请 / 企业邀请到打开 App”。N-FIRST-LOGIN/PERSONAL 展示无邀请首登；N-FIRST-AUTH/SPACES 展示邀请与桌面刷新。账号过期与受限在 J-PC-06 补充。企业创建、未安装/冷启动在 Spec PC-F05/C-R08 中已有文字规则，当前画布尚未单列所有这些节点；不能宣称画布已逐分支演练它们。

### 小王没有企业邀请

1. 打开桌面客户端，到登录页；认证方式引用 POL-112，不在此再选一次。
2. 登录成功，准备属于小王的唯一“我的空间”；无需先创建企业。
3. 到个人首页，看见固定助手。零常用时可以去“全部 Apps”，不自动挑 App；目录使用见 M03。
4. 下次打开，有效登录状态恢复，仍需核对空间访问权；登录过期则重新登录后回有权入口，不自动重做上次业务动作。

### 小王带着企业邀请

1. 在系统浏览器打开邀请，看清企业、邀请状态及默认成员身份。
2. 用被邀请的同一业务账号登录，再确认加入。指定邀请身份匹配后直接加入；共享邀请提交后等待企业管理员审批。
3. 加入成功，已安装则打开 Polo；未安装则下载后登录。浏览器加入成功不代表桌面已经更新。
4. 桌面重新取自己的企业列表；小王主动选企业后才进入企业首页。可以继续留在个人空间，其他设备不会被强制切换。

### 小王想创建自己的企业

客户端“创建企业” → 浏览器企业创建页 → 提交成功成为唯一 Owner → 返回桌面刷新列表 → 自己决定是否进入。不要求先拥有某家企业的管理身份；基础验证条件引用 POL-112。企业管理操作留到对应后台。

### 常见失败与恢复

| 小王遇到什么 | 页面反馈与下一步 |
| --- | --- |
| 个人空间还在准备 | 留在准备状态，幂等重试；不能每试一次创建一个新空间 |
| 登录了另一个账号 | 邀请页解释账号不匹配，改用受邀账号；不把邀请交给错误账号 |
| 邀请过期、已取消、次数用完 | 显示失效原因，不加入；从原渠道取得有效邀请 |
| 共享邀请仍待审批 | 保留待审批状态；可以先用个人空间，批准前不显示为可进入企业 |
| 浏览器已加入，但桌面没有企业 | 核对同账号并重试刷新；已成立的成员关系保留，不用重新接受或创建企业 |
| 客户端未安装或当时没开 | 下载/稍后启动，用同账号重新取列表；不依赖那一次返回信号 |
| 企业创建失败或取消 | 失败在浏览器保留已填信息并可幂等重试；取消未提交动作不创建企业；已创建成功不因关窗口而消失 |
| 登录过期、账号暂停或已被企业移除 | 过期重新认证；暂停/移除不能用重登或邀请绕过。企业无权则回仍有权个人空间或安全受限页 |

已有基础：登录、个人空间、邀请接口、桌面刷新接线。需补：把上述分支在实际环境完整接通并验证，尤其浏览器成功后桌面未刷新、未安装/冷启动、错账号及待审批。这里是接线和验收缺口，不需要用户重新决定共享身份规则。


**本轮范围：**保留登录承接、个人空间、企业邀请和创建返回；认证与找回引用 POL-112，不在客户端复制企业管理写操作。

**检查例子：**同一账号在浏览器成功加入后，桌面首次刷新失败；重试后能看到企业，且无需再次加入，也不自动切换其他设备。

## M02 个人与企业空间切换

对应 PC-F06 / S-004、S-005；画布 J-PC-02“日常：安全切换”。


入口是顶部当前空间名称。选择器只列“我的空间”和仍有效的企业；不把圈子、创作者后台或本地 Workspace 当成空间。

### 没有正在运行的任务

小王在甲企业首页，选“我的空间” → 系统验证目标访问权并加载目标 → 完整切换成功后展示个人首页。没有活动执行，不弹出终止任务确认。若从助手内切换，落目标空间的助手会话列表或新对话，不自动打开上次对话。选择只影响这台设备。

### 有 App 或助手正在运行

小王在甲企业有“报价整理 App”和一个助手回答正在生成，另一个 App 在同空间后台工作。

1. 小王选“我的空间”。系统列全当前空间 App、助手、AI 及后台活动，说明必须先停止。
2. 小王可取消，继续留在甲企业工作；或点“终止全部并切换”，不必逐一找任务。
3. 界面显示每项停止状态。只有全部确认停止，才加载并提交目标空间。
4. 切换成功后，原空间不再有后台任务。个人目录、助手、文件访问、Skills、权限与内部计量上下文同时生效，不闪现企业历史。

企业资料仍归企业，旧执行的实际费用仍归原执行所属空间；切换后的新执行按目标空间授权计量，不把旧账或企业内容搬到个人。首页不新增常驻付款方标识。

### 失败、取消及恢复

| 情况 | 处理 |
| --- | --- |
| 开始终止前取消 | 留原空间，原任务继续；上下文不变 |
| App 已停止，但助手停止失败 | 留原空间，逐项显示真实状态；提供“重试失败项”和“取消切换” |
| 上述部分停止后取消切换 | 已停 App 不自动重跑，尚未停止的活动保留真实状态；取消的是切换，不撤销已经完成的停止 |
| 全部停止，但目标加载失败 | 留在无混合数据的恢复界面；重试加载，或回仍有权原空间；已停任务不自动复活 |
| 目标企业已撤销小王资格 | 拒绝进入，并移除或标明不可用；回仍有权原空间，原空间也不可用则安全受限页 |
| 切换途中登录过期/客户端重开 | 重新验证账号、空间和实际运行状态，再提供有权入口；旧切换回执不自动完成新切换，不重发任务 |
| 正在使用的原企业也撤权 | 按 PC-F08 阻止操作、终止活动，安全回有权个人空间；个人不可加载则受限页，不用“返回原空间”绕过撤权 |

推荐处理沿既有 Spec：先停止，再整体切换；恢复只恢复合法可操作入口，不自动重做业务。上述取消、失败、数据与费用规则无需重复提问。

### 已有实现与待补齐

- 已有：POO-42 在已盘点 C-INT 基线具备空间选择、终止后提交、终止失败及受限处理，且有局部验收证据。
- 仍需补齐或验证：全部 App Tab 和助手后台活动接入；会话/附件/Skills/Browser 等所有资源一致切换；加载失败与旧回执竞态；真实运行中撤权、重开恢复。不能用局部通过推导整个模块已上线。


**本轮范围：**保留当前设备安全切换；不跨空间后台运行、不搬企业资料或旧任务费用到个人。

**检查例子：**App 停止成功、助手停止失败时取消切换：用户仍在原空间，已停 App 不自动重跑，界面准确显示其他运行状态。

## M03 首页与全部 Apps

**用户目标与入口：**小王登录后找到自己有权使用的 App，能把常用作品放到首页，也能移除不常用的入口。对应 PC-F02/07、PC-N01；画布 J-PC-01 的首页、全部 Apps 节点。

### 实际使用

1. 小王进入当前空间首页，看到固定的 Polo 助手和自己配置的最多 5 个常用 App。
2. 第一次还没有常用 App 时，首页明确提供“全部 Apps”，不自动挑作品。
3. 进入“全部 Apps”，查看当前空间完整目录。个人空间显示内置及圈子明确分发的作品；企业空间显示企业向本人分发的作品。
4. 打开前看名称、来源、版本和可用状态。同名但不同来源的作品分别呈现，不能互相覆盖。
5. 从目录直接打开 App，或配置首页常用入口。移出常用只改变快捷入口，不退出圈子。
6. 在个人空间可以隐藏、停用单个圈子 App；之后从仍然有权的圈子作品列表恢复。用户控制不替代服务端授权。

### 空状态、失败与恢复

| 情况 | 用户反馈与动作 |
| --- | --- |
| 常用为空，但目录有作品 | 引导去“全部 Apps”，不要说“没有可用 App” |
| 企业确实没分发作品 | 说明尚未分发，联系企业管理员；不能用个人圈子作品填充 |
| 个人目录确实为空 | 保留当前可用助手及已有邀请的使用路径，不虚构公开市场 |
| 目录加载失败或断网 | 显示失败/离线和可重试入口，不把失败显示成空目录 |
| 停止分发、订阅到期或版本被阻断 | 保留不可用原因，不能借常用入口或缓存启动 |
| 新版本发布 | 目录反映新稳定版本；已开始的运行继续使用启动版本，新启动再按规则取版本 |

**范围与实现：**保留目录、来源辨识、个人控制和常用入口；不做公开市场、关注信息流或首页统一任务队列。已有首页和 Catalog 基础；零常用引导、三类空/错态、控制后恢复及版本状态的全流程仍需补齐或验收。

**检查例子：**甲企业没分发“小王个人圈子里已有的 App”，企业目录不得显示或借用该 App；切回个人后才按个人授权找到。

## M04 App 使用与运行管理

**用户目标与入口：**从目录打开 App 工作，在需要时关闭、让它留在同空间后台、终止或重新打开。对应 PC-F02/07、PC-N02；画布 J-PC-01 和 J-PC-07。

### 实际使用

1. 小王从当前空间目录选中 App。首次需要准备运行载荷或确认权限时，客户端解释必要信息；对用户统一称 App，不要求理解本地、远程或沙箱类型。
2. 用户确认后，客户端准备并打开 App 标签页。已经准备好的 App 按规则直接打开。
3. 小王在 App 内选择材料、执行任务和查看内容。打开 App 与在 App 内执行业务是两个动作；Polo 不自动替他发起任务。
4. App 内业务页面、结果保存和历史由 App 自己负责。Polo 负责受信运行、空间隔离和平台状态。
5. 小王关闭没有活动执行的标签页时直接关闭；有活动执行时，提供“取消”“后台继续”“终止并关闭”。
6. 选择后台继续后，活动只留在当前空间；小王可从运行入口或应用列表重新打开/聚焦正确实例。切空间仍按 M02 全部终止。

### 失败、取消与恢复

| 情况 | 反馈与动作 |
| --- | --- |
| 准备或更新失败 | 说明可理解的原因，可主动重试或返回目录；不假装 App 已打开 |
| 权限确认取消 | 不启动依赖该权限的动作，返回原入口 |
| 系统拒绝文件等必要权限 | **本版恢复建议：**说明被拒权限和系统设置/重新选择路径，用户处理后主动重试；不增加新的权限种类 |
| 更新需要新增权限 | 重新确认新增权限，不能沿用旧许可直接扩大访问 |
| 终止超时或失败 | 保留标签页和原空间，显示真实状态，允许重试；未确认停止不能显示已停止 |
| 只取得部分结果 | App 解释其内容与保存状态；Polo 显示真实平台运行状态，不汇总或判断 App 结果 |
| 断网、崩溃或重开 | 先重验空间及访问权，再从有权列表重新打开；不承诺 Polo 自动恢复 App 的业务进度 |

**范围与实现：**保留运行状态、关闭/后台/终止与重开；App 结果聚合移出，创作者新 SDK/API 延后。已有目录启动和 Runtime 基础；App 标签页、后台重开、终止竞态与 OS 权限恢复仍需集成/验收。权限恢复建议尚未单独获新确认，不冒充此前已冻结交互。

**检查例子：**点击“终止并关闭”后平台没有确认停止，标签页仍在，用户能看到失败并重试，不会错误关闭另一个空间的同名 App。

## M05 Polo 助手

**用户目标与入口：**首页固定 Polo 助手 → 当前空间会话列表或新对话。小王选材料、向助手提问、查看回复，也可以回答助手追问。对应 PC-F04/07、PC-N04；画布 J-PC-04。

### 实际使用

1. 小王打开助手，页面持续显示当前空间。个人与每个企业的会话互相独立。
2. 选择本空间已有对话，或新建对话；首次没有对话时提供新建入口，不展示其他空间历史。
3. 在对话内选择材料并发送。助手只读取本空间允许的数据、文件和已启用 Skills。
4. 回复和实际保存的附件、生成文件留在原对话。以后回到该对话查看，不经过独立文件汇总页。
5. 用户可以主动停止生成；页面显示已停止，保留实际产生和保存的内容，不谎称余额不足。
6. 助手需要用户补充信息时，显示问题。用户可回答或暂不回答；回答只形成一条可读消息，并在原会话继续，暂不回答不自动续答。
7. 助手提问功能已有的问题状态及草稿恢复按原任务保留。重开后不会把同一答案重复提交；这不是所有 App/表单的通用草稿恢复承诺。

### 失败与恢复

| 情况 | 反馈与动作 |
| --- | --- |
| 文件读取权限被拒绝 | 不继续依赖该文件的动作，允许重新选择或处理权限后重试 |
| 回复只生成一部分 | 保留真实部分；按积分不足、网络或服务错误分别解释，不统一写成成功 |
| 发送前积分不足 | 不创建新消息，保留输入并引导处理，细节见 M09 |
| 用户回答时问题已失效/已回答 | 不重复提交；显示实际状态，不产生第二条答案 |
| 原会话删除或已无权 | 不把答案转投其他会话，回有权入口 |
| 短暂提交失败 | 先核对真实结果再重试，避免重复消息 |
| 登录过期/重开 | 重新验证账号和空间后恢复已保存内容；不自动发送原 Prompt |

**范围与实现：**保留助手自身对话、文件和恢复责任，不因“App 自管”取消这些能力。已有助手及相关交互基础；跨空间全资源隔离、持久化、部分输出、真实回答链路与重开仍需完整交付证据。

**检查例子：**企业助手追问时重开客户端，回有权原企业对话可处理原问题；切到个人助手不得看到该问题或收到迟到答案。

## M06 Skills 与助手工具

**用户目标与入口：**小王在助手内部查看可用 Skill、明确启用/停用，并使用已有工具能力。对应 PC-F04/07；画布 J-PC-04，工具深层操作仍以原助手能力与 Spec 的隔离边界为准。

### 实际使用

1. 进入当前空间助手的 Skills 入口，看名称、创作者/圈子或企业来源及状态。
2. 选择自己需要的 Skill 并明确启用。需要准备文件时由客户端处理，不能让“准备完成”代替本人启用。
3. 启用状态跟随同一用户、同一空间和对应 Skill，在本人设备间同步；不会替企业其他成员启用。
4. 回到对话，助手可按任务需要调用已经启用、且执行时仍有权限的 Skill。
5. 明确停用后，后续不再以“曾经启用过”为由调用。个人圈子 Skill 不自动获得企业授权。
6. Sources（数据来源）、Automations（自动化）和助手 Browser 继续在助手内部使用；相关配置、权限及后台执行随空间隔离。模型、终端、本地工作目录等只作为会话/高级上下文，不进入普通首页主导航。

### 容易混淆的三个状态

| 状态 | 对用户意味着什么 |
| --- | --- |
| 有授权 | 当前空间允许本人使用这个能力 |
| 本人已启用 | 用户选择让当前空间助手使用它 |
| 当前设备已准备 | 本机需要的文件或运行条件已就绪，不是另一套业务授权 |

没有授权，后两项不能绕过；有授权也不等于已替用户启用。

### 失败与恢复

同名 Skill 始终显示来源；启用时权限失效则拒绝，调用前失效则不调用并提示其他能力。紧急版本阻断终止相关调用；已保存历史不自动删除，但标记来源版本已被阻断。设备准备失败给重试状态，不能误报授权被取消；旧链接、跨空间链接或过期链接重验目标，不能在错误空间启用。

**范围与实现：**保留当前空间的本人启停和既有助手工具，不给 Skill 建独立 App 标签页，不允许 App 任意调用用户本地/未打包 Skill。已有部分组件；空间授权、启用同步、版本化链接、设备准备和工具资源隔离仍需补齐或完整验收。

**检查例子：**两个圈子都提供“表格整理”，小王能辨认来源；在个人启用其中一个，不会在企业或其他成员账号下自动启用。

## M07 我的圈子与订阅

**用户目标与入口：**从个人“我的圈子”管理已有关系，或从邀请、分享链接、二维码加入，取得明确分发的 Apps/Skills。对应 PC-F03、S-010/011/014/015/016；画布 J-PC-05。

### 免费或邀请加入

1. 小王打开链接，看到圈子、创作者、加入方式和分发内容说明。
2. 明确确认加入；需要审批时显示待审批，批准前不给作品权限。
3. 成员资格生效后进入圈子详情，看到“已获得的 Apps 和 Skills”。
4. App 由用户主动打开；Skill 转入助手内明确启用。加入本身不会自动开 App、启用 Skill 或创建新的空间。

### 付费加入、续费与退出

1. 用户核对价格、周期和续费规则，去系统浏览器确认订阅订单。该订单属于个人内容订阅，不使用企业付款上下文，也不能用计算积分抵扣。
2. 支付完成返回桌面，重新验证成员资格、刷新详情和作品；不把浏览器成功直接当桌面完成。
3. 沿用第二轮手动续费：30 天周期；到期前续费从原有效期末延长，最多累计 12 个月；到期后重新购买，无自动续费或宽限期。价格变化必须按新价重新确认。
4. 免费/邀请转付费、付费转免费和赠送资格按既有支付规则的过渡期处理，客户端展示服务端事实，不自行改期限。
5. 用户可确认立即退出，撤销后续作品授权；关闭确认框不退出。普通订阅到期停止新启动，但已预授权任务可自然结束；紧急全局阻断另按 M11。
6. 不给自己管理的圈子购买订阅；退款/争议走既有运营处理，不新增本轮自助按比例退款流程。

### 失败与恢复

| 情况 | 处理 |
| --- | --- |
| 尚无圈子 | 提示使用已有邀请/分享链接，不显示虚构公开市场 |
| 已加入但没有分发作品 | 说明尚无可用作品，不把成员关系显示为丢失 |
| 邀请失效、圈子停止加入 | 不建立关系，显示原因 |
| 已经加入 | 打开现有关系，不重复创建 |
| 支付取消 | 回详情；已完成的支付不会因返回或关窗口回滚 |
| 支付未知/处理中 | 保留真实状态，不重复扣款或提前授予 |
| 已付但桌面刷新失败 | 保留已付/成员事实并重刷，不要求重新购买 |
| 退出/到期后再次打开旧 App 链接 | 拒绝新启动，保留失效原因；恢复只能经允许的重新加入/购买 |

**范围与实现：**保留个人圈子关系、详情、手动订阅与生命周期；不建圈子空间、公开市场、自动续费或宽限期。已有关系摘要和浏览器部分页面/API；桌面详情、空态、返回刷新及退出/到期闭环需补。

**检查例子：**付费成功后断网，桌面不能显示“购买失败请再买”；网络恢复重取资格后可看到作品，且没有自动打开任何 App。

## M08 内容与文件去向

**用户目标：**小王知道工作产物到哪里看，哪些由 Polo 负责，哪些由 App 负责。对应 PC-F02/04/07/10、PC-N02；画布 J-PC-01 的 App 结果节点和 J-PC-04 的助手对话节点。

### 两条自然路径

| 内容来源 | 下次从哪里找 | 责任边界 |
| --- | --- | --- |
| 第三方 App 产出的内容 | 当前有权应用列表 → 打开该 App → 使用 App 自己提供的历史/保存能力 | App 负责保存、历史与业务恢复。Polo 不承诺每个 App 都有历史，不检查保存状态 |
| Polo 助手的消息、附件、生成文件 | 当前空间助手 → 原对话 → 打开对应消息/文件 | Polo 负责自身实际保存的数据及授权访问；独立跨对话文件汇总页延后 |

小王不需要执行“先保存到 Polo 才能离开 App”的步骤。企业内容仍归企业，App 自管不意味着内容可自动迁到个人，也不改变原费用责任。

### 文件打开与助手跨空间转移

- 从原助手对话打开实际存在且有权访问的文件。材料选择仍在 App/助手内部，不新增独立上传入口。
- 正常空间切换从不搬文件或会话。
- 既有助手显式导出/导入能力仅转移规则允许的内容；用户明确发起，目标空间创建新的对象。不携带凭证、隐藏上下文、权限或可继续调用原空间的引用。
- 不能证明归属的旧数据保持隔离，不静默分给当前账号或空间。具体允许导出的内容清单留对应实施设计，不凭本文扩大。

### 失败与恢复

文件被移走/删除时明确提示找不到，允许重新选择，不伪造找回。用户失去企业权限时不能通过旧附件路径继续访问。导出/导入取消或失败不产生可被其他空间读取的半成品；重开只恢复已合法保存的内容，不扩大为所有未提交草稿恢复。

**范围与实现：**D-PC-02/03 已确认；第三方 App 结果/文件聚合移出，独立文件汇总页延后。保留 App 可发现与打开、助手原对话文件及既有允许转移能力。已有部分附件/文件基础；需要验证原对话打开、文件丢失、转移和旧数据隔离，旧 POO-47/56/57 聚合要求后续裁剪，不新增重复任务。

**检查例子：**小王第二天要看 App 昨天生成的内容，Polo 让他从有权列表重开 App，不插入“找不到 Polo 保存记录”警告；App 是否提供历史由 App 自己决定。

## M09 积分不足与充值

**用户目标与入口：**小王在 App/助手中遇到平台积分不足，处理后自己决定是否再次执行。对应 PC-N03；画布 J-PC-03。

### 使用中看到什么

| 场景 | 客户端行为 |
| --- | --- |
| 助手发送前不足 | 不创建新消息；当前输入保留可编辑，发送不可用；输入框上方提示及处理入口 |
| 助手生成中耗尽 | 停止下一段生成，保留部分输出；只在消息末尾说明，不再重复输入框提示 |
| App 平台积分不足 | 保留 App 页面，显示非模态平台提示；不替 App 设计业务结果或自动续跑 |
| 用户主动停止 | 显示停止，不说积分耗尽 |
| 恰好正常完成后余额归零 | 不把成功任务写成中断 |
| 普通服务故障或结果未知 | 说明暂不可用/真实状态，不自行猜成积分不足 |

### 去浏览器处理，再回桌面

1. 个人用户可处理个人充值；企业 Owner 可处理企业充值；Manager/Member 使用“通知 Owner”，不看到企业财务细节。
2. “去充值”打开当前正确空间的浏览器支付页面，由用户选商品和付款，不替用户自动下单。
3. 回桌面后，用户点击“已完成，查询结果”，才发起一次查询。“还没有”只关闭询问。
4. 未到账、处理中或查询失败时保留明确状态与原阻断；需要再次查时，由用户再点一次。
5. 服务端确认已恢复且其他权限仍有效，只解除相应阻断；用户使用普通发送/执行动作决定后续，不自动发送、续写、重试或创建新任务。

浏览器支付页自己的查单行为不等于允许桌面自动查询。桌面获得焦点、浏览器返回、重开和定时器都不能自行查询充值恢复。切到其他空间或换账号后，旧订单回执不能解除新空间的限制。

### 费用、预算与恢复边界

没有可用输出不扣积分、不产生零金额账单；部分输出按实际使用结算。执行固定启动空间、App、版本及费率，不随中途目录或空间选择改写。企业预算超限由 Owner 调整预算；已预授权生成可结束，下一次发送受阻。充值不解除账号暂停、成员撤权或其他治理限制。

**范围与实现：**全部沿用 POL-94 第二轮确认，不改自动查询或自动重跑规则。已有支付/计量基础及设计；App/助手提示、角色动作、订单目标校验和人工恢复需完整客户端验收。

**检查例子：**浏览器显示付款成功后，桌面尚未查询仍保持原状态；用户点一次只查一次，确认恢复后也没有第二条自动发出的消息。

## M10 账号、偏好与管理跳转

**用户目标与入口：**账号菜单 → 账号与偏好；查看账号、安全、外观、通知、本机存储及授权记录，必要时进入有权后台。对应 PC-F09/S-007；画布 J-PC-06，身份原定义引用 POL-112 r11。

### 实际使用

1. 普通用户在客户端处理已有账号与偏好操作。企业管理、创作者生产、支付账单和复杂注销在对应系统浏览器页面处理。
2. 用户是某企业 Owner/Manager 时，才有相应企业管理入口；各企业分别鉴权。
3. 有效创作者可进入创作者工作台；资格暂停/撤销后仍有未结责任时，保留只读责任入口，不继续生产。
4. 企业与创作者后台各自维护登录状态；有效则进入有权目标，失效则在该端登录，不要求先退出另一个后台。普通用户没有必经三选一门户或 staff 快捷入口。
5. 用户退出本端登录，业务数据不被当作退出动作删除；重新登录仍要验证当前资格。
6. 手机号不可用时沿共享规则联系运营线下核验、恢复原账号；不另建自助申请/找回工单。恢复账号不改变原数据所有权、付款义务，也不恢复已撤资格。
7. 注销若有企业/创作者所有权或未结财务责任，在浏览器列出阻塞项并处理；不能靠桌面退出绕过责任。

### 常见失败与恢复

没有管理资格就不显示可写动作。链接打不开可重试；目标页仍要自己鉴权，不能凭客户端菜单曾显示就授予权限。后台登录过期重新登录后回有权原页及已保存内容，不承诺未提交表单恢复；权限已失效则拒绝或转责任只读。取消未提交动作回原入口，已提交操作须核实结果，不自动重放。

**范围与实现：**保留账号偏好及按资格跳转，不复制后台写操作，不提供 MVP 创作者自助申请。已有设置与独立后台入口；最新资格菜单、返回目标、过期恢复、只读责任和运营找回的实际接线/操作证据仍需补。

**检查例子：**小王同时是企业 Owner 和创作者，可分别进入两个后台，不必互相退出；企业财务与创作者收入仍是各自有权的业务范围。

## M11 受限、断网与重开

**用户目标与入口：**在启动或使用中遇到异常时，理解发生什么并找到安全的下一步。对应 PC-F08/10/11、S-006/016/022/023/060/062；画布 J-PC-06，并引用 M02/04/09 的恢复分支。

### 权限和作品变不可用

| 触发 | 用户看到及系统执行 |
| --- | --- |
| 正在使用的企业将小王移除或暂停 | 显示原因和联系管理员入口；阻止新操作并终止企业活动，安全回个人空间。企业数据不搬到个人 |
| 个人空间也暂不可用 | 留安全受限页，不继续展示企业内容 |
| 企业治理暂停、关闭中或既有欠费限制 | 按企业限制停止活动，Owner 去浏览器处理；普通成员不能绕过。与单次积分不足/预算上限分别判断 |
| 作品停止分发、退出圈子或订阅到期 | 停止新启动，保留具体不可用原因；不能通过缓存或旧链接继续执行 |
| 普通订阅到期 | 已预授权任务可自然结束，后续新启动受限 |
| 版本被紧急全局阻断 | 所有空间禁止启动该版本，终止相关调用；不把它当普通订阅到期 |

解除限制后只恢复仍合法的关系和可操作状态，不自动重启任务；充值或重新登录不能清除另一个尚未解除的限制。

### 离线和网络恢复

1. 离线打开时，只在有效数据归属范围内查看 Polo 已保存的本机助手历史、文件及缓存目录说明，明确缓存不是最新授权。
2. 离线不启动新的 App、助手或 AI 执行。运行中断网停止新的网络/AI 调用，显示等待恢复或终止；未知结果不显示成功。
3. 网络回来后重新验证空间、作品、版本和计量权限；用户再决定新动作，不自动重发旧任务。
4. App 内历史和业务进度如何恢复由 App 自己提供；Polo 只对自身容器和已保存数据负责。

### 客户端重开或必须升级

重开先恢复有效身份并重验空间，重取目录及有权助手数据；过期启动凭证不继续用，中断中的执行不猜成成功。客户端不能安全理解服务端空间规则时，阻止业务并提示升级/帮助；升级失败或取消仍停在阻断页。升级后重新校验，旧组织/圈子空间和授权缓存不能被误认成新的个人/企业空间。

**范围与实现：**保留这些安全恢复路径，不新增离线执行、跨空间后台或统一 App 结果恢复承诺。已有部分受限、目录离线和契约检查；完整活动终止、数据清理边界、联网重验、升级/帮助真实目的地及重开竞态仍需实测。

**检查例子：**小王断网期间已被企业移除，联网后不能先恢复企业 App 执行再检查权限；应先发现失权并安全退回。
