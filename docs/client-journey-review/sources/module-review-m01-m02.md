## M01 登录与进入空间：本次走查

画布沿用 J-PC-01“首次：无邀请 / 企业邀请到打开 App”。N-FIRST-LOGIN/PERSONAL 展示无邀请首登；N-FIRST-AUTH/SPACES 展示邀请与桌面刷新。账号过期与受限在 J-PC-06 补充。企业创建、未安装/冷启动在 Spec PC-F05/C-R08 中已有文字规则，当前画布尚未单列所有这些节点；不能宣称画布已逐分支演练它们。

### 小王没有企业邀请

1. 打开桌面客户端，到登录页；认证方式引用 POL-112，不在此再选一次。
2. 登录成功，准备属于小王的唯一“我的空间”；无需先创建企业。
3. 到个人首页，看见固定助手。零常用时可以去“全部 Apps”，不自动挑 App；此处只确认能进入，目录使用在 M03 细走。
4. 下次打开，有效登录状态恢复，仍需核对空间访问权；登录过期则重新登录后回有权入口，不自动重做上次业务动作。

### 小王带着企业邀请

1. 在系统浏览器打开邀请，看清企业、邀请状态及默认成员身份。
2. 用被邀请的同一业务账号登录，再确认加入。指定邀请身份匹配后直接加入；共享邀请提交后等待企业管理员审批。
3. 加入成功，已安装则打开 Polo；未安装则下载后登录。浏览器加入成功不代表桌面已经更新。
4. 桌面重新取自己的企业列表；小王主动选企业后才进入企业首页。可以继续留在个人空间，其他设备不会被强制切换。

### 小王想创建自己的企业

客户端“创建企业” → 浏览器企业创建页 → 提交成功成为唯一 Owner → 返回桌面刷新列表 → 自己决定是否进入。不要求先拥有某家企业的管理身份；基础验证条件引用 POL-112。企业管理操作留到对应后台。

### 常见失败与恢复

| 小王遇到什么 | 页面反馈与下一步 |
| --- | --- |
| 个人空间还在准备 | 留在准备状态，幂等重试；不能每试一次创建一个新空间 |
| 登录了另一个账号 | 邀请页解释账号不匹配，改用受邀账号；不把邀请交给错误账号 |
| 邀请过期、已取消、次数用完 | 显示失效原因，不加入；从原渠道取得有效邀请 |
| 共享邀请仍待审批 | 保留待审批状态；可以先用个人空间，批准前不显示为可进入企业 |
| 浏览器已加入，但桌面没有企业 | 核对同账号并重试刷新；已成立的成员关系保留，不用重新接受或创建企业 |
| 客户端未安装或当时没开 | 下载/稍后启动，用同账号重新取列表；不依赖那一次返回信号 |
| 企业创建失败或取消 | 失败在浏览器保留已填信息并可幂等重试；取消未提交动作不创建企业；已创建成功不因关窗口而消失 |
| 登录过期、账号暂停或已被企业移除 | 过期重新认证；暂停/移除不能用重登或邀请绕过。企业无权则回仍有权个人空间或安全受限页 |

已有基础：登录、个人空间、邀请接口、桌面刷新接线。需补：把上述分支在实际环境完整接通并验证，尤其浏览器成功后桌面未刷新、未安装/冷启动、错账号及待审批。这里是接线和验收缺口，不需要用户重新决定共享身份规则。

本模块没有新增产品选择；沿用已有规则，当前不提确认问题。下一模块 M02：有 App/助手正在运行时，小王如何在个人和企业间切换，以及取消和终止失败后回到哪里。
