## 先看结论

现有客户端不需要整体重画。11 个模块应按下面四类处理：

| 处理方式 | 模块 | 结论 |
| --- | --- | --- |
| 直接复用，做回归验证 | M05 助手、M06 Skills 与工具、M08 内容与文件去向 | 用户已确认现有助手功能、流程和框架可直接复用（D-PC-06）；不依据历史线框重做 |
| 复用主体，只补局部交互 | M02 空间切换、M04 App 容器、M10 账号与管理入口、M11 异常恢复 | 已有较多实现或集成候选；需要补齐确定的状态、入口和跨端返回 |
| 需要调整关键页面 | M01 登录后进入空间、M03 首页与全部 Apps | 当前源码行为与已确认方案有明确差异；先用真实页面做局部 Before/After，再制作所需高保真页面 |
| 当前客户端缺少完整页面 | M07 圈子与订阅、M09 积分不足与充值返回 | 已有业务规则和跨端流程，客户端入口或恢复页仍缺；先做关键节点线框，确认页面责任后再高保真 |

推荐下一步不是制作一套全新的“Polo V3”。先整理一份真实页面截图包，在同一份视觉评审中只处理四组变化：

1. **空间与身份入口：**M01、M02、M10。
2. **首页与 App 容器：**M03、M04。
3. **新增跨端节点：**M07、M09。
4. **异常状态：**M11。

M05、M06、M08只进入回归验收清单，不再要求用户审核重画后的日常界面。

## M01—M11 完整清单

### M01 登录与进入正确空间

**用户要完成的事**

新用户登录后可以直接进入“我的空间”；收到企业邀请或创建企业时，在浏览器完成身份动作，回桌面刷新企业列表，再由本人选择进入。

**当前证据**

- `dev` 的 `App.tsx` 会在桌面内渲染 `OrganizationOnboarding`，用于创建、加入或选择组织。
- `useOrganizationContext.ts:350-355` 在用户没有可用组织时进入 `create` 状态，并没有证明“我的空间”自动可用。
- `OrganizationSwitcher.tsx` 仍提供桌面内“创建另一个组织”和管理弹窗。
- ProductSpace 集成候选已建立个人/企业空间模型和启动契约，但这不等于浏览器邀请、创建、冷启动返回已经端到端闭合。

**与已确认方案的差异**

- 企业创建、邀请确认属于浏览器身份交接；桌面负责承接、刷新和进入，不应再维护一套桌面企业创建流程。
- 没有企业的用户也应有“我的空间”，不能被迫先创建企业。
- 浏览器成功不等于桌面成功刷新；错账号、待审批、未安装和冷启动都要有明确恢复。

**结论与材料**

- 分类：**调整；已设计未完全接线；跨端闭环证据不足**。
- 先看真实登录后页面、桌面组织引导和浏览器返回状态。
- 只为“创建/接受后回桌面”的局部入口和返回状态做 Before/After；无需重画认证页面，身份规则引用 POL-112。
- 高保真范围：若真实页面确认仍把企业创建放在桌面，只设计入口替换与返回状态，不制作新的完整登录体系。

### M02 个人与企业空间切换

**用户要完成的事**

从当前空间切到另一个空间；有活动时先看到全部活动，用户确认“终止全部并切换”。部分停止失败时留在原空间，可重试失败项或取消；不出现数据、权限、Skills、会话和计量上下文混用。

**当前证据**

- `dev` 的 `OrganizationSwitcher.tsx:63-80` 点击组织后直接调用选择动作；`useOrganizationContext.ts:574-580` 直接激活目标组织，没有在此路径看到终止全部活动的事务。
- ProductSpace 集成候选包含 `ProductSpaceSwitcher`、`ProductSpaceSwitchDialog`、终止进度、失败重试、目标加载失败及访问权丢失状态，并有定向测试。
- 集成候选尚不能证明所有 App Tab、助手生成、附件、Browser/Automation 后台活动都纳入同一停止清单，也没有当前部署验收证据。

**结论与材料**

- 分类：**集成候选可复用；当前 dev 未包含；完整活动覆盖仍需验证**。
- 直接以集成候选的真实对话框做视觉基线，不另画抽象线框。
- 评审时一次看完：无活动直切、有活动确认、部分停止失败、目标加载失败、撤权五个状态。
- 高保真默认不需要；只有真实候选页面与现有设计系统明显不一致时才做局部修订稿。

### M03 首页与全部 Apps

**用户要完成的事**

首页固定显示 Polo 助手和本人选择的最多 5 个常用 App；没有常用 App 时明确进入“全部 Apps”。目录展示当前空间有权使用的 App、来源、版本和可用状态。

**当前证据**

- `HomePage.tsx:50` 定义 `MAX_RECENT_APPS = 6`。
- `HomePage.tsx:208-265` 在打开 App 后自动写入最近使用记录。
- `HomePage.tsx:440-486` 首先显示“最近使用”，再显示内置 App；组织 App 目录已有加载、空、失败、离线、安装、更新、停止、卸载和日志等状态。

**与已确认方案的差异**

- 当前是“自动记录最近 6 个”，目标是“固定助手 + 用户主动配置最多 5 个”。
- 零常用时应引导“全部 Apps”，不能自动替用户选择。
- 企业目录不能混入个人圈子作品；个人隐藏/停用/恢复也不能等同于移出最近使用。

**结论与材料**

- 分类：**关键页面调整；目录主体可复用；个人控制流程待补**。
- 这是本轮第一优先级高保真页面：基于真实 HomePage 做局部 Before/After，覆盖“有常用”“零常用”“目录为空”“加载失败”四种状态。
- 保留现有 Catalog 和运行操作，不把高保真稿扩成新的公开市场或信息流。
- D-PC-07 已确认：沿现有首页视觉调整，不另起一套首页风格。

### M04 App 使用与运行管理

**用户要完成的事**

从目录打开 App 后，App 占用 Polo 主内容区，内部业务交互全部由 FDE App 负责。Polo 提供标签、返回/刷新等容器能力，并在有活动时处理后台继续、终止、重开和切空间前停止。

**当前证据**

- `TabShell.tsx` 和 `TabBar.tsx` 已有首页、Polo、Web App 标签与前进/后退/刷新。
- Web App 标签会占据主内容区，符合浏览器式容器方向。
- `TabBar.tsx:71-78` 的关闭按钮直接调用 `closeTab`；当前页面层未看到“取消 / 后台继续 / 终止并关闭”的活动判断。
- 本地 Runtime、目录安装/启动/停止/更新/取消和回滚有较多源码与定向测试。

**结论与材料**

- 分类：**容器主体直接复用；关闭与运行恢复需调整；完整验收不足**。
- 不评审任何 App 内部页面，也不依据示例 App 结果页创建 Polo 需求。
- 用真实 App 全屏容器截图，加一个“存在活动时关闭”的局部交互稿；同时展示终止失败后标签仍保留。
- 高保真只覆盖容器控制和关闭对话框，不画第三方 App 内容。
- D-PC-07 已确认：“后台继续”为普通操作，“终止并关闭”为危险操作；终止失败时保留标签页。

### M05 Polo 助手

**用户要完成的事**

在当前空间新建或打开对话，添加附件、发送问题、查看回答、回答追问、停止生成，并回原对话查看已保存内容。

**当前证据与已确认结论**

- 客户端已有助手框架、会话、附件、生成文件、追问与停止等能力。
- 用户已确认整个流程已跑通，框架直接复用（D-PC-06）。
- V2 原型只是历史演示，不是改版目标。

**结论与材料**

- 分类：**直接复用；只做回归验证**。
- 不制作线框或高保真稿。
- 后续验证范围只包括空间隔离、撤权、重开、部分输出、重复提交防护和积分阻断是否保持已确认行为。

### M06 Skills、附件与助手工具

**用户要完成的事**

在助手内查看并启用/停用有权 Skill，添加附件，使用 Sources、Automations 和 Browser 等既有工具；授权、本人启用和本机准备三个状态保持分开。

**当前证据与已确认结论**

- 现有助手已经具备 Skills、附件及工具能力，用户确认直接复用。
- 普通首页不需要新增独立 Skill 市场；App 也不能因此任意调用用户本地 Skill。

**结论与材料**

- 分类：**直接复用；空间授权与撤权做回归验证**。
- 不制作新的普通流程图、线框或高保真稿。
- 只有真实验证发现缺失状态时，才补对应局部错误状态。

### M07 我的圈子与订阅

**用户要完成的事**

在个人空间查看已加入的圈子；从邀请、链接或二维码查看详情，免费加入或等待审批；付费时去浏览器，返回桌面刷新；手动续费、退出和到期后理解哪些 App/Skill 已不可用。

**当前证据**

- 已确认文档和 Browser 端已有圈子加入、审批、支付、关系摘要等规则或局部能力。
- 在当前 `dev` 客户端已核对路径中，没有找到“我的圈子”产品页面、圈子详情或订阅返回页面。
- 现有 provider subscription、示例文案等不是本功能证据。

**结论与材料**

- 分类：**客户端当前未找到完整实现；跨端流程已设计；需要新增入口和返回状态**。
- 先做一组最小可点击线框：我的圈子列表/空态 → 圈子详情 → 待审批或去浏览器 → 返回刷新 → 到期/退出。
- 浏览器支付页由另一端负责，客户端只画交接前后的页面。
- 线框确认入口和状态责任后，再对“我的圈子列表、详情、返回状态”制作高保真；不做公开圈子市场。
- D-PC-07 已确认：“我的圈子”放在个人空间的稳定导航中，与“全部 Apps”并列，不放入账号设置。

### M08 内容与文件去向

**用户要完成的事**

App 业务内容、历史和找回由 App 自己负责；用户从 Polo 有权应用列表重新打开 App。助手附件和生成文件仍回原对话查看。

**当前证据与已确认结论**

- 用户已明确 Polo 是 App 容器，不统一保存或找回 App 业务结果（D-PC-02/D-PC-05）。
- 现有助手附件、文件预览和会话内内容直接复用。
- 独立文件汇总页和面向创作者的新 SDK/API 已延后。

**结论与材料**

- 分类：**责任边界已确认；助手直接复用；不新增 Polo 结果页**。
- 不制作线框或高保真稿。
- 后续只验证助手原对话文件、文件缺失提示、跨空间隔离，以及旧任务是否仍误导性地实现统一结果聚合。

### M09 积分不足与充值返回

**用户要完成的事**

执行前或生成中遇到 ProductSpace 积分不足时看到准确状态；个人用户可去浏览器充值，企业成员通知 Owner。浏览器返回后由用户主动单次查询，看到最新事实后自己决定是否重新执行。

**当前证据**

- ProductSpace 集成候选的 Runtime 和 API Gateway 已识别 `insufficient_credit`、`metering_unconfirmed`，并有计量顺序与幂等测试。
- 当前已核对客户端页面中没有找到完整的 ProductSpace 充值入口、浏览器返回后单次查询和角色差异页面。
- 现有 LLM provider billing 设置属于另一套能力，不能当成 ProductSpace 充值实现。

**结论与材料**

- 分类：**底层计量候选已实现；桌面交互与跨端闭环未找到完整实现**。
- 先做最小线框：发送前不足、生成中不足且有部分输出、个人去充值、企业成员通知 Owner、返回后“查询最新状态”、查询失败。
- 高保真只覆盖桌面阻断卡片和返回查询状态；浏览器订单/支付页沿 POL-94 和对应端设计。
- 固定规则：不自动查询、不自动发送、不续写、不重试原任务。
- D-PC-07 已确认：使用 Polo 容器级提示，让不同 App 获得一致反馈，并提供用户主动“查询最新状态”的单一动作。

### M10 账号、偏好与管理端跳转

**用户要完成的事**

从账号菜单管理账号、安全、外观、通知、本机存储等偏好；有资格的用户进入对应浏览器后台，并在返回客户端后刷新相关事实。

**当前证据**

- `settings-pages.ts` 已注册应用、账号安全、外观、输入、Workspace、权限、标签、消息、服务器、快捷键、偏好等页面。
- `OrganizationSwitcher.tsx:82-97` 按组织类型或角色显示管理项和“创建另一个组织”，但当前动作进入桌面 `OrganizationManagementDialog`。
- `OrganizationManagementDialog` 包含成员、邀请和组织管理写操作，与已确认的浏览器独立管理端边界存在差异。

**结论与材料**

- 分类：**设置直接复用；业务管理入口需调整；资格与返回验证不足**。
- 用真实账号菜单与设置页作基线，不重画偏好设置。
- D-PC-07 已确认：企业管理、创作者工作台、平台后台等所有管理入口统一放在账号菜单；不再把当前空间管理入口放在空间选择器。
- 对账号菜单中的资格显示、无资格状态和浏览器返回做局部 Before/After；不复制浏览器后台页面。

### M11 被移除、版本受限、断网与客户端重开

**用户要完成的事**

成员被企业移除、App 被停用或版本阻断、网络断开、客户端重开或契约不兼容时，用户知道发生了什么，并回到仍有权、安全且不会自动重做业务的入口。

**当前证据**

- `useOrganizationContext`、App Catalog 和 HomePage 已有部分撤权、缓存、离线、空/错态处理。
- ProductSpace 集成候选包含只读/受限空间、ContractGate、安全切换失败与上下文隔离，并有定向测试。
- 本地 Runtime 对崩溃、安装更新失败、校验失败、取消和清理有较多测试。
- 这些局部证据没有覆盖真实环境中的“运行中撤权 → 停止全部 → 安全退回”“浏览器处理后桌面刷新”“真实升级下载失败”等完整旅程。

**结论与材料**

- 分类：**部分实现；集成候选可复用；端到端证据不足**。
- 不新增一套异常中心。使用真实页面逐状态回放：目录离线、运行中撤权、版本阻断、ContractGate、重开恢复、升级失败。
- 默认用标注截图和验收矩阵；只有某个状态没有承载页面时，才补局部线框或高保真错误页。

## 哪些情况用线框，哪些用高保真

### 先用线框

- M07 圈子在客户端的入口、列表、详情和浏览器返回，因为当前客户端没有完整页面可复用。
- M09 积分阻断和返回查询，因为底层错误存在，但用户看到的页面责任尚未形成完整实现。
- 任何实际核对后仍然找不到承载页面的新异常节点。

线框只回答“页面从哪里来、用户按什么、结果到哪里、失败怎么回”。

### 可以直接做局部高保真

- M03 首页，因为目标规则已确认，且当前 HomePage 有明确可复用基线和明确差异。
- M04 有活动时关闭 App 的对话框，因为容器已有，缺口集中在一个局部交互。
- M10 账号菜单中的管理端资格入口和返回状态，因为设置主体已有，缺口集中在菜单与跨端反馈。

高保真应沿当前设计系统和真实组件制作，不能把历史 V1/V2 概念稿当作新的视觉基线。

### 不做新视觉稿

- M05 助手。
- M06 Skills、附件和工具。
- M08 App 结果责任与助手原对话文件。
- M02 已存在的 ProductSpace 切换候选，除非真实页面核对发现具体可用性问题。
- M11 已有承载页面的异常状态。

## 后续实施规划输入

视觉对齐完成后，Plan 应按差异拆分，而不是按 11 个模块全部重做：

1. **确认真实集成基线：**决定以 `dev` 还是 ProductSpace 集成候选为实施起点，并重新核对远端和部署版本。
2. **直接复用清单：**锁定 M05/M06/M08，防止旧原型制造无意义改版任务。
3. **局部修改清单：**M01、M03、M04、M10。
4. **新增客户端节点：**M07、M09。
5. **集成与验收清单：**M02、M11，以及所有跨空间、跨端、撤权、断网和重开场景。
6. **跨端依赖：**身份与入口继续引用 POL-112；支付/充值引用 POL-94；浏览器成功只作为桌面刷新输入。

在真实页面截图和部署版本尚未核对前，本文只确定“需要看什么、为什么看、用什么材料”，不把源码存在写成已上线，也不启动产品编码。
