## 1. 创建企业

场景：ENT-F01；S-003、S-029；J-ENT-01 / N-ENT-01；验收 AC-ENT-01、11。

**例子：小林准备给团队开通 Polo，目前还没有企业管理身份。**

**入口与操作**

1. 从 Polo 创建入口或合法创建页进入，按 POL-112 完成账号验证。
2. 填写企业名称、主要用途，确认企业付款责任。
3. 提交创建，系统同时建立企业、企业空间及唯一 Owner，小林成为 Owner。
4. 进入简洁概览/首次配置，可继续邀请成员、导入工具、准备企业算力，也可稍后回来。
5. 在 Polo 空间列表发现企业，由小林主动切换，不强制改变当前空间。

**成功结果：**企业和责任人完整建立，可以继续配置。创建本身不要求已有工具或先充值；开始需要算力的执行前，Owner 须准备企业余额，企业不享有个人试用积分。

| 常见情况 | 结果和恢复 |
| --- | --- |
| 验证、资料或付款责任确认缺项 | 指明缺项，补齐再提交；不建立半个企业 |
| 提交超时或重复点击 | 查询原结果；已成功返回同一企业，未成功才安全重试 |
| 登录过期、离开页面 | 重登录恢复已保存结果；不自动重复创建，未提交表单不承诺恢复 |
| 暂无员工、工具或余额 | 保留企业，显示空状态和下一步，允许分步完成 |
| Polo 未打开或空间尚未出现 | 保持浏览器管理页面可用，按共享规则提供打开/安装引导并重新查询空间，不要求再次创建 |

**范围与实现：**保留简单开通，不新增复杂入驻流程。集成源码已有创建页和成功页，继续配置目前去成员页；目标概览、跨端同步和刷新后安全重试仍需验收。推荐沿用“先开通、再分步配置”。

## 2. 企业概览与切换

场景：ENT-F02；S-023、S-029；J-ENT-01、03；验收 AC-ENT-08、11。

**例子：小林第二天回到后台，想知道团队是否已经配好工具。**

**入口与操作**

1. 登录独立企业后台，或从 Polo 中有权限的管理入口打开。
2. 有指定企业时先验证该目标；无目标时恢复上次仍有管理权限的企业。
3. 概览展示当前企业、成员与工具配置、限制原因及下一步操作。
4. 有多个企业时，通过切换器选另一个企业，页面重新加载其数据和权限。
5. Owner 可进入财务查看金额和预算；Manager 只获得其权限内的配置、限制及处理提示。

**成功结果：**管理员知道还缺邀请、工具启用或费用准备中的哪一步。后台“已启用”只代表配置结果，不能宣称员工设备已安装或已经运行成功。

| 常见情况 | 结果和恢复 |
| --- | --- |
| 企业没有工具或只有 Owner | 显示空状态及导入、邀请入口，不当作系统故障 |
| 页面加载失败 | 显示重试；不能用空列表冒充企业数据不存在 |
| 指定企业无权访问、角色刚变化 | 拒绝该企业数据访问，重新按当前权限选择入口；不沿用旧角色 |
| 欠费、治理暂停或关闭处理中 | 先解释限制，指向有权限负责人能处理的事项 |
| 会话过期 | 按 POL-112 重登录回仍有权页面和已保存内容 |

**范围与实现：**保留简洁概览和切换，成员诊断专页延后。POL-105 的概览在所查任务分支有实现，但未证明其当前版本进入集成；已有可用性计算也不能证明另一员工的设备状态。推荐复用概览，补自然入口与权限投影。

## 3. 成员邀请与管理

场景：ENT-F03、ENT-F04、ENT-F06；S-030、S-031、S-033；J-ENT-01、06；验收 AC-ENT-02、07。

**例子：管理员邀请 Alice 入企，之后 Owner 调整她的角色或处理离职。**

### 3.1 指定成员邀请

1. Owner/Manager 在“成员与邀请”填写指定联系方式，生成默认 7 天有效的邀请。
2. Alice 打开公开邀请页，看到最少必要的企业信息、邀请人和默认 Member 身份。
3. 按 POL-112 登录匹配的账号，回到邀请页确认，直接加入，无需再次审批。
4. 成功页引导打开或下载 Polo；同一账号的空间列表出现企业，Alice 主动进入。

### 3.2 共享邀请与申请审批

1. 管理员设置有效期、人数上限和说明，生成共享链接/二维码。
2. Alice 登录后提交申请，处于待审批状态，暂不获得企业访问权。
3. Owner/Manager 审批通过后，Alice 以 Member 加入，再进入 Polo 使用。
4. 管理员可查看待接受、待审批、已加入、拒绝、过期、撤销等状态，并撤销或重发邀请。

### 3.3 角色、暂停与离职

1. Owner 在成员页选择晋升 Manager、降为 Member、暂停、恢复或移除。
2. 高风险动作展示影响、确认及原因，保存前复核目标当前状态。
3. 成功后立即更新权限。新成员可获取全部已启用工具，但仍需本人完成 App 安装或 Skill 启用。
4. 被移除成员不能再使用企业；活动企业执行终止，客户端清理可操作企业上下文并安全返回个人空间。企业数据不转给个人。

| 常见情况 | 结果和恢复 |
| --- | --- |
| 指定邀请登录了错误账号 | 不转移邀请，按 POL-112 切换到受邀账号，再回原邀请 |
| 过期、撤销、人数用完 | 不入企，管理员核对后重发或调整邀请 |
| 申请待批或被拒 | 展示真实状态，不展示企业内容；由管理员处理申请 |
| 已经加入，又打开邀请 | 返回原成员关系，不重复加入 |
| 账号或企业成员被暂停 | 新邀请不能绕过限制，先处理对应暂停原因 |
| Manager 改成员角色/状态，或普通操作移除唯一 Owner | 拒绝；角色/状态由 Owner 操作，Owner 退出先转让 |
| 页面过期或他人已修改成员 | 刷新最新状态后重新确认，不覆盖并发操作 |
| 加入成功但客户端目录加载失败 | 保留成员关系，同账号查询空间和目录，不反复加入 |

**范围与实现：**保留指定邀请、共享审批、基本角色和状态，组及组后续配置延后。POL-79/80 已有页面、接口和历史局部验收；客户端加入/撤权全链及旧组 UI 收缩待核。推荐沿用现有两类邀请，不新增审批层级。

## 4. App/Skill 导入、启用、停用与移出

场景：ENT-F07、ENT-F08、ENT-F12 的作品移出部分；S-034、S-035、S-037；J-ENT-01；验收 AC-ENT-03、04、05。

**例子：小林从交付方拿到“报价整理 App”，要让 Alice 使用。**

**入口与操作**

1. Owner/Manager 打开“App/Skill 工具”，上传交付包和必要说明。没有包时可稍后导入，不默认存在应用商店。
2. 系统读取类型、来源、版本及校验信息，执行检查。管理员查看检查中、通过、警告或失败及原因。
3. 检查通过后形成企业独立管理的实例，先处于可配置状态。
4. 管理员明确启用，开放给全体有效成员。单纯上传成功或检查通过不等于已经开放。
5. Alice 在 Polo 企业空间获取工具：App 首次安装确认后打开；Skill 由 Alice 本人启用，在该企业助手中使用。
6. Alice 得到真实结果，才算首次使用成功；数据和实际算力费用属于当前企业。

**后续操作**

- Owner/Manager 可停用，停止新的启动或调用；业务数据不自动删除。普通停用与治理阻断、撤权的执行终止规则分别适用。
- 再启用时重新满足检查、企业和平台治理条件，不绕过全局阻断。
- Owner 可将实例移出企业目录。移出不代表 App 业务数据已删除。
- 管理员不能修改包内版本、代码或 Skill 内容；修改由交付方交新包，再上传检查。

| 常见情况 | 结果和恢复 |
| --- | --- |
| 缺来源/版本、包损坏、检查失败 | 不进入成员目录；显示原因，找交付方修包后重新上传，保留检查记录 |
| 重复导入同一包 | 返回已有实例或明确的新候选版本操作，不静默覆盖 |
| 上传中断或离开页面 | 未完成上传重新提交；已登记实例和检查从工具页查询，避免盲目重传 |
| 检查通过但员工看不到 | 管理员先核对是否启用、企业/成员是否有效；员工确认企业空间并重查目录 |
| 员工看得到但不能用 | 按提示区分安装、本人 Skill 启用、余额/预算及治理限制，不把“可见”当作可运行 |
| 欠费、治理暂停或版本被阻断 | 不新增分发或启用；正确负责人处理原因后再检查 |
| 停用后员工打开旧链接 | 禁止新的启动/调用，旧链接不能绕过当前状态 |

**范围与实现：**全员分发保留，员工客户端创作/导出/共享延后。POL-85/86 有服务/API 和原型；完整导入页面及跨端实际使用证据不足。本人启用与深链由 POO-52 后续 POO-63/64 承接。推荐补齐现有链路，不新造同名开发卡。

## 5. 版本更新与回退

场景：ENT-F09；S-036；J-ENT-02；验收 AC-ENT-06。

**例子：交付方修好报价计算，小林收到新版包。**

1. Owner/Manager 进入该工具详情的版本区，上传新版，形成候选版本。
2. 查看包内版本、变更说明、检查和治理结果。
3. 检查通过后明确“采用”。上传本身不替换当前版本。
4. 已开始执行继续使用启动版本，之后的新执行使用新采用版本。
5. 如需回退，选择本企业曾保留且仍允许运行的版本，明确确认回退。
6. 保存上传人、采用人、时间和版本历史。

| 常见情况 | 结果和恢复 |
| --- | --- |
| 新版检查失败或被阻断 | 不能采用，原有效版保留，交付方修包后重传 |
| 采用失败或并发修改 | 不部分切换成员；刷新当前状态再确认，失败保留原版 |
| 取消、离开页面或会话过期 | 已上传候选可重查；未确认采用不切版，不自动重放操作 |
| 没有可回退版本 | 显示无可用候选；交付方提供可用包，不虚构恢复成功 |
| 交付方发布新版但企业未收到包 | 不自动提醒、同步或生成候选版本；收到新交付后再上传 |

**范围与实现：**保留手动采用/回退，不做来源自动订阅。POL-85/86 有版本服务及历史局部验收，完整企业 UI 和运行中版本衔接待验收。推荐保持显式采用，避免交付方更新直接影响全员。

## 6. 财务、预算与受限恢复

场景：ENT-F10、ENT-F02/12 的费用限制部分；S-023、S-033、S-054；J-ENT-03；验收 AC-ENT-05、08、09。

**例子：Alice 使用工具时算力不足，小林需要处理费用。**

### 6.1 平时查看和付款

1. Owner 在当前企业的“财务”查看余额、消耗记录/成员汇总、自然月预算、订单及付款状态。
2. 按第二轮支付方案进入本企业充值，确认订单与付款目标，完成支付。
3. 回订单查看支付及积分发放结果；支付处理中或已支付待发放，不冒充到账。
4. 在相应记录处理退款、发票及必要导出。退款按原付款人/渠道与可退批次处理，不转为新 Owner 个人资产。

### 6.2 控制预算和恢复使用

1. Owner 可以设置企业级自然月预算；未设置也是允许状态，不做成员或组配额。
2. 余额与预算分别判断：余额不足要充值；预算触顶需要 Owner 处理预算，充值不自动抬高预算。
3. 员工只看到无金额的受限说明，并沿既有路径通知 Owner，不新建通知系统。
4. Owner 处理后，员工主动检查一次；条件满足后手动开始，不自动重跑原任务。
5. 预算达到硬限时禁止新付费执行，已授权任务可在授权范围内完成；欠费限制、治理暂停或 closing 终止活动执行，解除后不自动重启。

| 常见情况 | 结果和恢复 |
| --- | --- |
| Manager/Member 打开财务入口或深链 | 拒绝财务详情；页面、接口、导出和审计都不能泄露金额或成员用量 |
| 付款结果未知、付款后未发放 | 保持真实处理中状态，从原订单继续查询，不重复扣费或发放 |
| 离开支付页面或关闭浏览器 | 服务端付款事实保留，再回原企业订单查询；离开页面不等于取消支付 |
| 充值后仍不能执行 | 区分预算触顶、治理暂停、成员暂停等独立限制，找对应负责人处理 |
| 预算被另一操作修改 | 刷新最新值，再确认，不用旧页面覆盖 |
| 当前企业发生切换 | 原订单仍绑定原企业，不能把支付结果记入新选企业 |

**范围与实现：**保留已确认第二轮支付、基础预算和财务责任，不新增高级分析。POL-103/104 的订单、消耗记录有实现和历史验收且所查已集成；旧账单允许 Manager 查看与后续规则冲突，须修正服务端授权。真实支付、发放及客户端恢复仍需跨端验收。推荐复用现有支付范围，并分别验证预算与余额。

## 7. 企业设置、Owner 转让、受限恢复与关闭

场景：ENT-F02、ENT-F05、ENT-F12；S-023、S-029、S-032、S-037、S-039、S-055；J-ENT-07；验收 AC-ENT-12、13。

### 7.1 资料与操作记录

Owner 从企业设置维护企业名称、用途和关键资料。重要变更记录操作者、对象、时间和结果；无权修改被拒绝，旧页面并发提交刷新后重试。审计按角色展示，Manager 不因能看管理记录而看到财务信息。

### 7.2 转让企业负责人

**例子：小林离开公司，把负责人转给现任有效 Manager 小周。**

1. 小林选择小周，查看付款、成员治理和关闭等责任变化。
2. 重新验证身份并确认。
3. 系统一次完成小周成为 Owner、小林变为 Manager，始终保持唯一有效 Owner。
4. 未付订单先安全关闭，已付待发放继续处理；企业余额、订单和历史留在企业。
5. 小林失去 Owner 专属财务和高风险权限，结果记入审计。

目标不是有效 Manager、目标或企业状态变化时，整次失败，保持原责任关系；刷新后重新选择，不留下双 Owner 或无 Owner。取消确认不转让。

### 7.3 Owner 失效和治理限制

- 唯一 Owner 失效时，有效 Manager 按既有平台人工路径提出恢复申请，平台验证企业与申请人后处理所有权；普通 Manager 不能自行升级。
- 账号找回与身份验证沿 POL-112；不在企业端新增另一套恢复身份的规则。
- 平台治理暂停时，Owner 保留账单、必要导出和申诉等责任入口；充值不能解除治理暂停。
- 限制解除后恢复原生命周期状态，不自动恢复被独立停用的成员/工具，也不自动重启任务。

### 7.4 关闭企业

**例子：公司不再使用，仍有一笔退款未完成。**

1. Owner 从设置发起关闭，企业进入“关闭处理中”（closing）。
2. 停止新邀请、作品导入、分发变更、购买和新执行，活动执行按限制规则终止。
3. 页面列出账单、退款、数据导出、所有权和其他未结责任；Owner 继续处理这些事项。
4. 平台人工核清后确认“已关闭”（closed）。退款未完成等未结事项会阻止最终关闭，明确说明卡在哪里。
5. closing 期间可按原规则撤销关闭，但不能借此解除独立治理限制。

**数据责任：**停用工具、移出目录和关闭企业都不等于业务数据已删除。每个 App 的实际保存位置、保留与删除方式按其声明核对；导出/删除通过 App 自身能力或平台人工支持处理。未取得真实存储确认，不能显示“数据已删除”。

| 常见情况 | 结果和恢复 |
| --- | --- |
| Manager 发起转让、关闭或关键资料写入 | 拒绝，由 Owner 处理；Owner 失效走人工恢复 |
| 有未付、已付待发放、退款或其他责任 | 分别显示真实状态及处理路径，未核清不最终关闭 |
| 高风险提交后网络中断 | 重查所有权/生命周期当前结果，不自动再次执行 |
| 不清楚 App 数据是否已导出/删除 | 继续核对 App 能力或人工处理，保留未完成状态 |
| 关闭过程中账号会话过期 | 重登录回仍有权责任页面，已保存状态保留，不重放关闭确认 |

**范围与实现：**保留基本资料、唯一 Owner、人工恢复、责任清算与必要审计；不做固定天数后自动关闭，不做通用删数据。POL-79/80 有转让及治理基础，POL-92 有历史清算验收，但所查最终 HEAD 的集成覆盖不足；资金、数据及平台交接仍需验收。推荐保留人工最终核责。

## 8. 工具故障与线下支持

场景：ENT-F11，关联 ENT-F07/09；S-038、S-056；J-ENT-05；验收 AC-ENT-10。

**例子：Alice 发现报价 App 报错，管理员联系交付方修复。**

1. Alice 向管理员反馈，小林通过现有线下渠道联系交付方。
2. 小林主动选择并提供必要报错信息，不因此给交付方后台账号或企业内容访问权。
3. 交付方修复后交新包，管理员回工具页上传、检查并采用。
4. Alice 手动再使用并核对结果；未解决继续线下跟进，不能标成已修复。

修复包检查失败就返回交付方处理，原有效版保留；可回退时使用仍可运行的旧版。会话中断后从企业版本记录找回已保存状态，不重复采用。

**范围与实现：**企业在线限时支持、站内工单及新增线上材料授权延后；保留线下处理。POL-106 还含平台紧急访问，不能整卡取消。推荐复用既有沟通渠道和正式版本流程。

## 9. 统一恢复规则与验收例子

各模块共同沿用：

- 会话过期按 POL-112 返回仍有权限的原页与已保存内容；未提交表单不承诺恢复。
- 取消或关页面不撤销已保存的邀请、付款、版本、转让或关闭事实；先查结果，不自动重放写入。
- 空状态说明“尚未配置什么”，失败说明“为什么没成功、接下来怎么做”，不能混用。

- 企业权限与限制服务端复验，旧链接、缓存和按钮隐藏不能替代授权。
