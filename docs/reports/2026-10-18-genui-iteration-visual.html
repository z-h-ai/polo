1P0-1 · 纯视图交互客户端闭环 第 1 波

要迭代什么：现在表格的排序/分组已经在客户端，但筛选没有；更重要的是边界没有制度化——模型会为"换个地区看看"生成走模型的按钮。迭代后：视图态操作（筛选/排序/分组/列选择）全部本地完成，action-buttons 只留给语义动作。

现场对比演示：点下面的筛选 chips 感受两种路径

地区 ⇅营收 (USD) ⇅同比增速 ⇅单数 ⇅
示意演示：数据为演示值。"走模型路径"模拟一轮会话往返（此处压缩为 ~2.5s 动画，真实场景含上下文装配与生成，通常更久）。

怎么迭代（3 步）：

  1. 先写边界契约（1 行字）：render_ui 工具描述与 system prompt 增加 "view-state operations are client-side; reserve action-buttons for semantic follow-ups"，顺手修 system.ts 里已知的 "no host bridge" 口径漂移。
  2. 表格加列筛选：文本列 = 值去重 chips（即上方演示形态），数值列 = 区间；全部 ephemeral React state，不进 schema、不持久化（与 confirm-flow 门链同一原则，回放语义零影响）。
  3. 测试收口：筛选纯函数单测 + 既有 genui-datatable-rows.test.ts 保持全绿（证明没有破坏既有行操作/回放）。
改动文件：packages/ui/src/components/markdown/MarkdownDatatableBlock.tsx（已有 sortKey/groupKey 基础）· GenUICard.tsx · session-tools-core/tool-defs.ts · prompts/system.ts

2P0-2 · render_ui 骨架流式预览 第 1 波⚠️ 需会签

要迭代什么：现在卡片要等工具调用完全结束才出现（TurnCard 只认 completed）。迭代后：模型还在生成 payload 时，先出现"正在构建 data-table《Sales by Region》"的骨架卡（只有类型+标题，不含业务数据），完成后无缝替换为正式卡片。底线不动摇：用户依然永远看不到未通过校验的 UI。

现场对比：同一次生成，左右同步播放

t = 0.0s 左＝现状（等 completed）｜右＝迭代后（骨架先出）· 同一份输出流驱动
模型输出流（render_ui 的 tool input 增量，~800 字节示意）
现状 · 卡片等工具调用 completed
用户见到第一张卡：t = —（此前只有工具运行指示）
迭代后 · 检测到完整 type+title 即出骨架
骨架可见：t = — · 正式卡：t = —（蓝色段＝骨架在场时间）
示意演示（流速度可视化加速；时间为页面实测）。骨架检测只认已完整闭合的 "type"/"title" 键值对；业务数据只在 completed 且 Zod 校验通过后出现——"永不显示无效 UI"的底线两侧都不变。

怎么迭代（4 步，最险一步先写失败测试）：

  1. 先写隔离失败测试：断言 tab 协议页收不到新事件 tool_input_delta（对齐 POO-103 把 ui_state 排除在 SessionEvent 联合外的同一纪律）——这步是本项的安全锚，测试不绿不继续。
  2. 加窄协议事件：只对 render_ui 发射（按 toolName 过滤）、250ms 节流、累计 8KB 即停；Claude 路径从 SDK 流的 input_json_delta 发射（原料已核实存在），Pi 路径维持现状降级。
  3. 骨架扫描器：纯函数，从累积的 partial JSON 里提取完整的 type/title 键值对 → 骨架卡（上图右栏形态）。
  4. completed 替换：走既有 mergeGenUiComponents 的 id 合并路径，骨架 → 正式卡无缝切换。
改动文件：protocol/dto.ts（新事件+常量）· claude-agent.ts（发射）· SessionManager.ts（扇出隔离 ⚠️）· TurnCard.tsx（累积+骨架）· 新增 genuiSkeleton.ts + 测试

3P1-1 · 工具 schema 瘦身 第 2 波

要迭代什么：render_ui 的工具 schema（zodToJsonSchema 产物）估算 4-6K token，每个会话每轮都付——比 OpenUI 描述 40+ 组件的 5,031 token 还贵，而我们只有 6 个组件。迭代后：结构留 schema、语义进目录一行式，目标 ≤2K。

token 消耗对比（模型每轮可见的输入成本）

现状 · render_ui schema（估算）
est. ~5,000 tok
迭代后目标
≤ 2,000 tok
参照 · OpenUI 全组件库 system prompt（实测 40+ 组件）
5,031 tok
现状：三处重复说同一件事
// schema 里 describe() 写一遍
value: z.number().describe(
  'Metric value. Numbers render with ' +
  'locale formatting…')
// system.ts 再写一遍
// "stat-card (single metric + delta)…"
// 目录 one-liner 第三遍
迭代后：一处一责
// schema 只留结构
value: z.number()
// 目录 one-liner 承接语义（160 字符
// sanitize 信任边界不变）
// `- stat-card — single metric with
//    optional delta and trend`
第 1 波的 P2-2a 脚本先量出真实基线（当前 4-6K 为估算值），柱状图以实测数字刷新后再动刀。

怎么迭代（4 步）：

  1. 实测：schema-size 脚本量 Claude .shape 与 Pi JSON Schema 两条路径的字节/token，基线写回 Plan。
  2. 三处去重：schema describe() / system.ts 节 / 目录 one-liner 的重复语义只留一处（结构必需留 schema，用法性进目录）。
  3. 约束下沉：非功能性 min/max 字符约束改为目录一句话（Zod 校验仍在，只是模型侧少付 token）。
  4. 复测 + 防回归：前后对比表 + CI 阈值（超基线 +20% 报警）；错误率观测（配套 P2-3 错误码）确保瘦身不伤生成质量。
改动文件：session-tools-core/tool-defs.ts · genui-catalog.ts · prompts/system.ts · 新增 scripts/genui-bench/schema-size.ts

4P1-2 · chart 组件（重开 ADR 0021）第 3 波

要迭代什么：现在要出一张图只有两条路——降级成表格，或升级成 512KB 整页 HTML。ADR 0021 自己写的重启条件 (a)"交互循环落地且 schema 稳定"已被 POO-103 满足，决策可以正式重开：经 render_ui registry 缝新增 chart 卡类型。

迭代后的 chart 卡长这样（样机）

AI
月度营收趋势
payload ≤4KB + 数据在 data/revenue.json（与 data-table 同一 src 文件化语义）
现状 · 要出图整页 HTML ≤512KB · webview · 全量重写迭代生成慢 / 成本高
迭代后 · chart 卡payload ≤4KB + src 文件 · 行内卡片 · id 原地更新输出 token 与首卡延迟双降
样机为自研极简 SVG 形态（bar/line 起步，无轴库、无 CDN、无运行时加载——严格落在 ADR 0021 自己划的缝里）。

怎么迭代（5 步）：

  1. 决策先行：新 ADR supersede 0021 的 P1 决定，引用其预设缝"render_ui registry 新卡类型"。
  2. schema 演进：chart 加入 SCHEMAS map；GENUI_RENDER_UI_SCHEMA_VERSION 1→2 并注册 v1 快照——POO-104 预留的回放机制迎来第一个真实消费者（旧 v1 卡片按生成时版本校验，未知版本 fail-closed 只读视图兜底）。
  3. 渲染器：ChartCardView（SVG bar/line 最小集：网格线+数值标签）注册进 GENUI_COMPONENT_REGISTRY。
  4. handler 复用：src containment 校验走 data-table 同一路径（realpath 限会话 data/）。
  5. 复测 token：用第 2 波的尺子确认 chart 的加入量，视觉走真实截图验收。
改动文件：docs/adr/00NN（新）· tool-defs.ts · genui-schema.ts（版本+快照）· genui-catalog.ts · GenUICard.tsx · render-ui.ts + 新测试

5P1-3 · 画布应用增量编辑 第 2 波⚠️ 需会签

要迭代什么：现在改画布应用里的一条数据，模型也要重发整个 512KB HTML（updateOf 全量重写）。迭代后：数据与结构分离——可变状态放 data/ JSON，改数据只需一个新工具 update_app_data 写小文件 + 秒级推送给已挂载的卡。

迭代前后：用户说"把预算改成 50 万"之后发生什么

现状链路
用户"把预算改成 50 万"
➜
模型重新生成整页 HTML≤512KB 逐 token 输出数十秒 · 高 token 成本
➜
webview 整页重载version+1 全量替换
迭代后链路
用户"把预算改成 50 万"
➜
update_app_data写 data/state.json（~1KB）秒级 · 低成本
➜
ui_state 点对点推送既有通道 · 不广播
➜
卡片局部更新结构不动 · 无重载
机制：bundle 用 <meta name="polo-app-data"> 声明数据依赖（≤3 个文件），attach 时宿主注入初值、更新时经既有 postUiStateToCard 推送——全部走既有围栏（realpath 限会话 data/、≤1MB、ephemeral 不持久化），零新信任根。

怎么迭代（4 步）：

  1. 围栏先行：先写路径逃逸/符号链接/超限的失败测试（仿 webview-genui-partition.isolated.ts 的写法），再实现 meta 声明解析 + attach 注入。
  2. 新工具：update_app_data(appId, dataSrc)，注册条件完全复用 generate_app 的 canvas 资格矩阵与三层 deny。
  3. 模型侧引导：generate_app 工具描述加一句"mutable state 放 data/ JSON、数据迭代用 update_app_data、结构变化才 updateOf"。
  4. 端到端验证：update → 已挂载卡收到新 ui_state；未挂载时仅落盘、下次 attach 注入。
改动文件：tool-defs.ts · 新增 handlers/update-app-data.ts · ui-card-registry.ts（meta 读取+注入）· handlers/genui.ts · dto.ts 常量 + 测试

6P2 配套三项（小而必要）

第 1 波P2-2 · 自有基准（尺子）

三层：a schema/payload token 计数脚本（第 1 波就位，P1-1 的前置）；b 格式投影对比（未来任何格式实验用）；c 真实生成基准（N 条 prompt × 模型 × 4 次，量结构有效率/首卡延迟，需预算单独立项）。

scripts/genui-bench/schema-size.ts（新）

第 1 波P2-3 · 错误码 taxonomy

Zod issues → 稳定错误码（unknown-component / missing-required / payload-too-large…）→ 每码一句修复提示。模型重试一次成功率提升；错误码计数同时是 P1-1 瘦身前后的质量观测数据源。

handlers/render-ui.ts + errorcodes 测试（新）

第 3 波P2-1 · 画布数据自动刷新（P1-3 跟进）

声明文件变化 → fs watch（防抖 ≥1s）→ 既有 ui_state 通道自动推送。画布应用从静态快照变为会话内活体，等价 OpenUI 的 Query 轮询但数据源限定在会话 data/ 围栏内。会话删除/卡卸载即注销 watch。跨会话/网络数据源明确不做（不破坏围栏模型）。

7迭代怎么跑：节奏、闸门、验收

  1. Plan 评审（当前）：plan.md 为 draft——工程师评审 + 两个⚠️项（P0-2 / P1-3）技术负责人会签，置 accepted 后才允许动 genui/impl。
  2. 按波推进：每波内并行、波间按依赖；每项收口跑 bun test（相关测试文件）+ typecheck:all + lint，证据贴卡（self-verify）。
  3. 每波验收：browser/visual 项（P0-1 筛选操作、P0-2 首卡提前、P1-2 chart 截图、P1-3 端到端推送）组一张集中验收卡，真实会话里走查。
  4. 防回归：schema token 进 CI 阈值；协议隔离测试（协议页收不到 tool_input_delta / ui_state）永久保留。
  5. 质量观测：P2-3 错误码计数对比 P1-1 前后的一次重试成功率——瘦身不达质量线即回滚该批精简。
明确不迭代的（报告 §6）：DSL 化输出、多框架渲染器、A2UI、浏览器直连工具、40+ 组件扩张——每一条都有拒绝理由，不因对方热闹而重开。
