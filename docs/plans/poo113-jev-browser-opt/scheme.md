# POO-113：浏览器操作「快慢分层」优化方案（Jev 替代路线）

> 状态：方案 + 测评设计（2026-10-22）。分支：`POO-113/feature/jev-model-browser-opt`

## 1. 背景与 Jev 调研结论

### 1.1 Jev 是什么

[TypeSafe AI](https://typesafe.ai) 于 2026-09-15 发布的 **System One Model**（命名取自 Kahneman《思考，快与慢》的"系统 1"）：

| 维度 | Jev | 传统 LLM |
|---|---|---|
| 输出形态 | 从**预定义 schema 的选项菜单**中做类型化决策，附带校准置信度；不生成自由字符串 | 自由文本生成 |
| 端到端延迟 | **70–500ms** | 3–329s |
| 输入价格 | $0.042/MTok，输出免费 | $0.2–10/MTok，输出约贵 5 倍 |
| 官方对比收益 | 同等 System One 智力下快 40–200×，评测口径最高 193.6× 更快 / 444.6× 更便宜 | — |
| 类型安全 | 数学保证 schema 匹配（0% 类型错误），因不生成字符串而"无法幻觉" | 依赖后处理解析 |

浏览器操作方向的公开案例（LangChain、Browser Use 原型、社区 Playwright 实验）的共同模式：**把 DOM/a11y 树索引成"合法操作 + 目标元素"的枚举菜单，让 Jev 从菜单里选**，而不是让 LLM 自由生成动作。

### 1.2 为什么不用 Jev 本体

- 国内网络环境访问 `typesafe.ai` 延迟不可控，且无官方国内端点；
- Jev 输出的是"选项索引 + 置信度"，需要专门适配层；
- 结论：**借 Jev 的"菜单化快速决策"思想，用国内低延迟快模型复刻这一层**。

### 1.3 polo 现状（问题定义）

现状链路（见 `docs/plans/poo109-open-built-in-browser/plan.md` 与代码）：

```
主会话模型（用户选定，思考强度通常 medium/high）
  → 读 browser_tool snapshot 输出（@eN + role + name 的文本 a11y 列表）
  → 自己挑 @eN、自己决定下一步动作
  → browser-tool-runtime.ts 纯文本解析执行（无模型参与）
```

- **每一步元素定位/动作决策都消耗主模型高思考档推理**：一次典型浏览器任务 10–30 步，主模型逐步决策是延迟与 token 成本的大头；
- 仓库已有但未接入浏览器链路的设施：`call_llm` 次级模型工具（`packages/shared/src/agent/llm-tool.ts`）、`getMiniModel()` 快模型选择（`packages/shared/src/config/llm-connections.ts:256`，按 "mini/flash/haiku" 关键词挑选）、每会话 `miniModel` 注入（`packages/server-core/src/sessions/SessionManager.ts:5396`）。

## 2. 方案：多路平行筛选 + 高思考 LLM 仲裁

### 2.1 架构

```
                       ┌────────────────────────────────────────────┐
 snapshot (@eN 菜单)   │  System One 层（快模型，多路并行，目标 ≤2s）   │
 ────────────────────►│  A 路: glm-5.3-flashx  (reasoning_effort=low)│
 加任务指令 + 动作历史  │  B 路: deepseek-flash   (thinking=disabled)  │
                       └───────────────┬────────────────────────────┘
                                       │ 两路一致（exact-match 命令）
                                       │   → 直接执行（auto-accept，不等主模型）
                                       ▼ 两路分歧 / 格式非法 / 任一输出 done|fail
                       ┌────────────────────────────────────────────┐
                       │  System Two 层（会话主模型，高思考档）         │
                       │  只在分歧时仲裁：两路答案 + snapshot → 定夺    │
                       └───────────────┬────────────────────────────┘
                                       ▼
                       browser-tool-runtime 照常执行（不变）
```

关键设计（对齐 Jev 的三个核心思想）：

1. **菜单化输入**：a11y snapshot 本身就是"合法目标菜单"（@eN 枚举 + 可执行动作集合固定枚举：`click|fill|select|scroll|key|navigate|done|fail`）。快模型只做**选择**，不做生成——输出约束为单条命令，杜绝长篇推理。
2. **校准置信度的国内替代**：快模型 API 不返回概率，用**多路一致性当置信度**——A/B 两路（或同模型双采样）结论一致 ≈ 高置信；分歧 ≈ 低置信，升级仲裁。这与 Jev 的 calibrated confidence 语义等价且无需改模型。
3. **快慢分工**：明确的 step（点哪个元素、填什么值、滚动多少）走快层；任务级规划（多步拆解、异常恢复、验收判断）仍由主模型在会话循环里做——本方案不替代主模型的规划职责，只接管"下一步动作"这一高频决策点。

### 2.2 决策规则（伪代码）

```ts
type FastPath = { model: 'glm-5.3-flashx' | 'deepseek-flash', command: string };

async function nextAction(pageSnapshot, task, currentSubGoal, history): Promise<string> {
  // currentSubGoal：主模型规划的当前子步骤指令（如"点击「登录」"）。
  // 硬约束（§5 实测）：快层只做定位执行，绝不传入整任务让其自规划。
  const [a, b] = await Promise.all([callFast('glm', ...), callFast('deepseek', ...)]); // 并行，互不等待
  const norm = (c) => normalizeCommand(c);            // 容错：空白、引号、@e 大小写 + 中文动词保险丝
  if (a && b && norm(a) === norm(b) && isExecutable(norm(a)))
    return norm(a);                                    // auto-accept：≈ 快层延迟
  return await arbiter(pageSnapshot, task, currentSubGoal, history, [a, b]); // 主模型高思考仲裁
}
```

- `isExecutable`：动作动词 ∈ 枚举、`@eN` 存在于当前 snapshot、fill/select 带参数。非法即触发仲裁——这是"类型安全"的国内版兜底。
- 仲裁 prompt 给主模型两路候选 + 理由，要求择一或另给答案；主模型也可判定 `done`/`fail`。
- 执行结果（成功/失败 + 新 snapshot 摘要）回填 history，供下一步决策。

### 2.3 快层筛选 Prompt（本方案随附，测评直接使用）

```
你是浏览器自动化系统中的快速决策器。根据页面快照与任务，输出下一步动作命令。

规则：
- 只输出一条命令，禁止解释、禁止多行、禁止 markdown。
- 命令格式（动词 枚举固定，必须与 browser_tool 实际子命令集保持一致）：click @eN | fill @eN 值 |
  select @eN 值 | upload @eN 绝对路径 | scroll down|up 像素 | key 键名 | navigate URL |
  done | fail: 原因
- @eN 必须来自快照实际存在的引用。
- 任务目标在当前页面已达成 → 输出 done。
- 快照信息不足以决策 → 输出 fail: <原因>。

## 页面快照
{snapshot}

## 任务
{task}

## 已执行动作
{history}

## 下一步命令
```

### 2.4 polo 接入点（实施映射）

| 改动 | 位置 | 说明 |
|---|---|---|
| 快层调用器 | `packages/shared/src/agent/` 新增 `browser-fast-decider.ts` | 并行两路 OpenAI 兼容调用（bigmodel v4 + deepseek），带超时（单路 3s）与降级（失败即走仲裁） |
| 模型配置 | `packages/shared/src/config/llm-connections.ts` | `getMiniModel()` 已有 flash 关键词选择逻辑，新增浏览器快层专用连接配置（provider/baseURL/key/model/参数：glm→`reasoning_effort:"low"`；deepseek→`thinking:{"type":"disabled"}`） |
| 触发时机 | `packages/shared/src/agent/browser-tool-runtime.ts`（`snapshot` 命令输出处） | snapshot 返回时附带"建议下一步动作"，主模型可直接采纳；或新增 `browser_tool --suggest` 子命令由主模型显式调用 |
| 仲裁 | 会话主模型自然承担 | 主模型收到两路分歧时由现有 agent 循环处理；也可在快层返回结果里带 `needs_arbitration: true` 标记 |
| 复用 | `call_llm`（llm-tool.ts）机制 | 快层调用可复用其次级模型请求管道与凭据管理 |

> 实施建议分两期：**P1** 仅做"snapshot 附带建议动作"（只读、零风险、立刻省主模型 token）；**P2** auto-accept 通道（两路一致直接执行，需用户开关确认）。

### 2.5 安全边界

- 快层只输出"下一步命令"，不改变浏览器工具的权限/审批链（Explore/Safe 模式规则不变，`prerequisite-manager.ts` 的先读文档门不变）；
- `navigate` 到站外域名、`upload`、涉及支付/删除类 `click` 一律不 auto-accept，强制走主模型审批；
- 快层超时/异常静默降级到现状链路（主模型自己挑），永不阻塞。

## 3. 测评设计（见 `testcases.jsonl` + `eval/`）

- 24 条案例（8 易 / 8 中 / 8 难），覆盖搜索、登录、表单、表格分页、弹窗遮挡、禁用态、目标已达成（done）、信息不足（fail）等；

- 对照组：
  1. **基线** = GLM-5.3 高思考单模型全量决策（≈ polo 现状架构）；
  2. **快层单路** = deepseek-flash（关思考）；
  3. **完整方案** = 双路并行 + 一致 auto-accept + 分歧仲裁（仲裁 = GLM-5.3 高思考）。
- B 路直连通道：bigmodel v4 + `reasoning_effort:"low"`（初测所用 key 无效，后换有效 key 完成直连实测，另有一次 coding plan 子代理通道作为通道对照）。

### 4.1 成本核算（快层为实测 token × 官方定价，原始数据 `eval/results/cost.json`）

| 项 | 官方单价 ¥/百万 token（入/出） | 实测 token/次 | 单次/单步成本 |
|---|---|---|---|
| A 路 deepseek-flash | 空闲 1 / 4；高峰 2 / 8（缓存命中 0.02–0.04） | 346 入 / 8 出 | ¥0.00038（空闲）– 0.00076（高峰） |
| B 路 glm-5.3-flashx | 2 / 7（缓存命中 0.57） | 361 入 / 8 出 | ¥0.00042（系统提示缓存）– 0.00078 |
| **快层两路并行（每步）** | — | — | **¥0.0008 – 0.0015** |
| 仲裁步 GLM-5.3（估算） | 8 / 28（刊例价） | ~15K 入 / ~500 出（含思考输出） | ~¥0.13 |

**10 步典型任务**：方案 ≈ **¥0.12**（快层 ¥0.01 + 0.83 步仲裁 ¥0.11） vs 现状（主模型做每步）≈ **¥1.34** → **约 1/11**。要点：

1. 快层本身近乎免费（¥0.001/步）；**方案成本的大头是仲裁步（约 90%）——分歧率就是成本杠杆**：8.3% 时仲裁开销可控，若分歧率升到 50% 以上，省钱优势将被侵蚀（快层 prompt 质量直接决定分歧率）。
2. 延迟收益同步兑现：10 步任务从每步 5.6–10s（合计约 1–2 分钟）降到常态 0.9–2.9s/步（合计约 10–30 秒）。
3. Jev 官方价对照：$0.042/M 入（≈¥0.3/M）、输出免费，同规模单步两路约 ¥0.0002——比本方案便宜约 5 倍，但两者绝对值都已可忽略，且 Jev 国内不可直连。
4. 价格口径：deepseek 分空闲/高峰（工作日 9–12、14–18 为高峰）；GLM-5.3 为刊例价；仲裁步 context 为估算（15K 入为典型会话中值，实际随任务长度浮动）。

结论（B 路直连复测后定稿）：

1. **System One 判断成立且两路快模型都够格**：deepseek-flash（关思考）与 glm-5.3-flashx（low）全对率均为 91.7%，与高思考基线三方持平；延迟分别 0.9s 与 2.9s（vs 基线 5.6–10s）。菜单化单步决策确实不需要高思考推理。
2. **跨模型分歧 8.3%（H02/H08）恰好落在双方盲区，仲裁修正后管线 95.8%（严格口径，无任何归一化）**：H02（评论区不在快照，应滚动探索）deepseek 双样本拒绝、flashx 样本 1 正确滚动 → 分歧 → 仲裁采纳滚动 → 修正。同模型双采样相关性太高（deepseek 24/24 一致仍含一致错误）——置信度信号必须来自跨模型，架构判断被实测证实。
3. **危险动作实证**：flashx 样本 1 在 H08 拿不准时输出了 `click @e2`（「保存」按钮）——快层 auto-accept 必须配 §2.5 的危险动作黑名单（保存/删除/提交/支付类 click 一律升级主模型），此条从设计假设变为实测依据。
4. **枚举完备性与通道无关性是硬约束**：动词菜单漏一个 `upload`，快层全部退化为 `fill`（修复前后实测对照）——上线时菜单必须由 `browser-tool-runtime.ts` 子命令表自动生成。快层 prompt 必须走专用精简 system prompt：同一模型在通用 agent 通道下全对率掉 10 个点、格式违规 ~10%（中文动词），在直连专用 prompt 下 100% 合规。
5. 遗留：H08（`select --assert-text`）全模型漏旗标，属 prompt 规格表述问题，P1 实施时把旗标写进动作枚举示例；同义词归一化（点击/上传→click/upload）降级为保险丝（仅仲裁层 GLM-5.3 偶发中文动词，1/24）。

## 5. 公开基准重测（Mind2Web，对 §4 合成集结论的修正与确认）

用 [Mind2Web](https://osu-nlp-group.github.io/Mind2Web)（osunlp/Mind2Web，HF）真实站点轨迹重测：80 个真实任务（travelzoo/amazon/marriott/united/qatarairways 等）取 135 个决策步，菜单 35–75 元素（英文，含容器噪声），两口径对照——

| 口径 | A 路 deepseek | B 路 flashx | 跨模型分歧 | 一致但错 | 仲裁救回 | 端到端管线 |
|---|---|---|---|---|---|---|
| 整任务自规划（越权：快层自己定下一步） | 40.0% | 46.7% | **46.7%** | 33/135 | 42%（12 例抽样，GLM-5.3 高思考） | ~48%，不可用 |
| **定位执行（方案口径：主模型给当前子步骤）** | **95.0%** | **88.3%** | **8.3%** | 2/60 | **5/5 全对** | **96.7%（58/60）** |

结论修正：

1. **合成集（§4）高估了快层的绝对能力**：91.7% 是"短菜单 + 干净中文合成页面"下的数字；真实英文页面 + 70 元素菜单下，快层整任务口径只有 40–47%。用户对测试集代表性的质疑被证实。
2. **方案的职责切分被真实数据验证**：快层"弱在规划、不弱在定位"。给它主模型规划的当前子步骤后，真实页面上 95%/88%（回到合成集水平），分歧率 8.3%、一致但错仅 2/60、5 个分歧仲裁全对——**端到端 96.7%**。置信度门控（一致才 auto-accept）只在定位口径下有效。
3. **实施硬约束（新增进 §2）**：快层输入必须包含"主模型规划的当前子步骤指令"，绝不拿整任务自规划；定位口径下分歧率 8.3% 与成本模型（§4.1）一致，整任务口径 46.7% 分歧会让仲裁开销失控。
4. 已知局限：Mind2Web 为静态单步数据，ground truth 取标注者单一规划路径（合理的替代规划会被判错，绝对值被低估——近失审计显示 34 个 wrong-element 中 8 个为同名/等价近失）；多步轨迹、真实浏览器执行反馈仍需 v3 评测（P2 auto-accept 前建议先跑 polo 内置浏览器实测 10–15 条端到端任务）。

| 环节 | 数量 | 正确 | 说明 |
|---|---|---|---|

| 升级仲裁（分歧 15 + 一致但危险动词 7） | 22 步（16.3%） | 19（86.4%） | 7 个危险一致案例仲裁全部确认原答案（无安全漏放） |
| **端到端** | **135 步** | **129（95.6%）** | 高于最优单路（A 路 94.8%），且危险动作全部经审 |

v2 相对更新的意义：

1. **95.6% 端到端在真实英文长菜单上成立**，且 83.7% 的步骤完全不消耗主模型；均步成本 ≈ ¥0.023（快层 ¥0.002 + 16.3%×仲裁），约为主模型逐步（¥0.134）的 1/6。
2. **危险动词黑名单零代价**：7 个"一致但危险"案例仲裁全部确认原答案——黑名单没有牺牲准确率，买到的全是安全边际（H08 类误点保存按钮的场景被系统性拦截）。
3. 剩余 6 个错例中 2 个为同名重复元素近失、1 个为 select 选项文本格式差——真实执行成功率会高于此静态口径；结构性改进方向是子步骤指令携带位置线索（§5 启发 1）与 a11y 树容器降噪。
