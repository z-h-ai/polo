# 桌面容器与本地 Skill · 本轮输入（2026-09-20）

用户要求：更新现有 mvp-complete-flow-hifi 原型；登录页面和配色可保留。Polo 是 macOS Electron 壳，应用是通过 SDK 调用文件系统、AI Provider 等能力的 Web App，最终员工无需理解此技术形式。Polo 助手是内置应用，参考 Craft Agents。Skill 仅供助手使用，内置和圈子 Skill 均需本地管理。企业空间组织内部固定流程应用和同事共享的 Skill；圈子为没有制作能力的个人用户补充应用和 Skill。用户授权根据竞品研究和 UX 判断推荐并直接修改。

## 本轮推荐（待复看，并非已批准的产品规则）

1. 普通应用点击即在标签内打开，关闭标签直接回首页。Polo 不复制应用自己的执行步骤、历史或结果页；仅展示中性的内容承载区。正在通过 SDK 执行后台任务时才出现三选项关闭确认，保留原已确认的后台恢复边界。
2. 文件权限仅在应用实际请求读文件时出现；加载失败有重试和返回。应用不要求员工安装 Skill 或配置 Provider。普通目录不暴露 SDK、Web App、API Key 等实现细节。
3. 助手保留三栏会话结构。侧栏的 Skill 页面用中栏导航本机/获取，右侧列出名称、来源、本机版本和启用状态。内置 Skill 可关闭不可卸载；分发 Skill 可安装、启停、更新、卸载。安装成功默认停用，由用户明确启用。安装副本属于本机；启用偏好沿用既有账号＋空间＋Skill 同步规则。启停影响后续消息，不终止正在执行的任务。卸载只移除本机副本，保留对话和源作品。
4. 企业共享库只在企业空间显示；圈子只服务个人空间。获取内容与本地启用分离。企业库中同事发布的 Skill 可下载安装到本机；员工可把自己的本地 Skill 提交企业审核。审核与发布并不等于企业已经授权给所有人。
5. 圈子应用用“打开”，圈子 Skill 用“安装到本机/管理本机版本”。本地副本不绕过授权；最后来源失效保留副本并停用，恢复来源后重新验证。多圈同一作品仍只出现一次，保留有效来源。
6. 个人/企业目录、助手和 Skill 操作保持当前空间；不通过个人圈子补企业授权。已确认的登录、计费、空间安全切换与来源恢复规则仍保留。

## 调研依据（读取日期 2026-09-20）

- [Craft Agents 官方仓库](https://github.com/craft-ai-agents/craft-agents-oss)：桌面会话管理、资料来源、本地文件、按 workspace 保存的 Skills；借鉴助手结构，不复制其整个功能集合。
- [Codex App 官方介绍](https://openai.com/index/introducing-the-codex-app/)：提供独立的 Skill 创建和管理入口，支持按任务使用技能；借鉴能力管理和对话的衔接，不引入面向开发者的 worktree 操作。
- [WorkBuddy 官方 Skill 文档](https://www.codebuddy.ai/docs/zh/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)：区分本机已安装与推荐技能，支持本地包导入、启停、搜索和卸载；借鉴本机生命周期。
- [WorkBuddy 官方介绍](https://cloud.tencent.com/product/workbuddy)：以自然语言完成办公任务、处理本地文件。Polo 的企业固定流程通过应用提供确定入口，这是结合用户目标的设计推论，不声称竞品采用 Polo 的空间/SDK 模型。

## 交互范围

浏览器仅验证离线原型；安装、文件选择、企业提交、网络恢复均为声明场景，不写真实系统和企业数据。真实安装失败、权限失效、来源到期等由评审控制台进入；产品页只出现恢复操作。正式设计确认、生产实现和端到端验收另行进行。

## 示例数据整理

本轮用同一创作者的晨星增长圈与晨星设计圈共同分发“增长案例检索”Skill，沿用 D-PC-09 的同作品多来源规则；不再让“会议纪要”按钮跳到另一款 Skill。付费来源到期或退出后，仍有效的免费来源继续支持安装/使用；仅最后来源失效时阻断。这些名称和来源均为原型虚构数据。内置 Skill 用“资料研究”完整演示管理生命周期，其余内置条目在本轮代表页不重复铺陈。
