## Closure

用户持有账号、邀请/分享链接、获授权作品、自己的资料和任务意图 → 桌面登录与当前空间首页（网页加入/付款由对应 Browser 入口承接）→ 系统识别账号、空间、作品、授权来源和版本 → 在正确空间打开 App 或使用助手 → 正确 App 容器、原会话消息/文件、同一圈子/原订单权益结果构成终态证据。

## Outside-in acceptance

1. 无邀请从桌面登录，应获得唯一我的空间；无使用记录仍能发现已有授权作品，真空与失败分开。
2. 退出增长圈，应只去掉增长来源；会议纪要另一设计来源有效，增长独占作品不能新开。取消退出应不改任何来源。增长退出→首页→圈子列表已实际重放。
3. 停用内置资料研究→首页→管理技能，内置保持停用，圈子同名作品不变。已实际重放，证据 `builtin-*.png`、`cases2.json`。
4. 文件权限拒绝→首页→助手，输入新文本仍不可发送；应有重新请求入口。已实测，`permission-new-blocked.png`。
5. 两份同名导出文件分别导入，预览/新对象/初次打开各自内容正确；然后经“所有会话”分别重开两个对象，内容、标题及来源不能互换。前半段通过，后半段失败 F-OBJ-01。
6. 已导入对话→首页→打开助手，应展示当前会话真实标题，或真正新建空会话；不能显示新聊天但附带旧对话内容。失败 F-OBJ-02。
7. 未兼容契约选择稍后处理仍阻断；已实测。真实下载完成后的重新验证留生产验收。
8. 企业已失权时所有企业操作保持禁用，返回个人不能重新授予企业权限；当前代码变动需最终版本重新动作验证。
9. Member 预算/积分不足只请求 Owner；Owner/个人充值返回每点击一次查询一次，失败保留事实、到账不重发；真实 API/金额/网络证据未执行。
10. 待答问题在原会话恢复；重复提交、已回答、过期、已删除不产生新会话消息；原型状态页齐备，真实重启/竞态证据待实施。

## Findings

### F-OBJ-01 · pending repair · 导入新对象缺自然找回路径

来源：PC-F04 转移入口与终态、C-R05/07；新增原型 transfer 行为，不要求重画真实 Renderer。

例子：先导入标题“同名材料”、文本“独立对象1金色鹦鹉”，再导入同标题、文本“独立对象2金色鹦鹉”。两个预览、确认与初次打开各自正确；随后点击“所有会话”，只剩固定“个人资料整理”，并显示原有样例对话，找不到任一新对象。第二次导入后 per-scope 最近结果替换，第一对象也没有自然恢复选择器。

推荐：将新导入对象按系统生成的独立 ID 接入原型既有会话列表；标题来自选择文件，两个同名对象保留可辨上下文，能分别重开对应内容。保留当前真实 Renderer UI 复用边界，只补新增转移的消费者。修改后用两份新同名文件重放“导入→列表→分别打开→首页往返”。

证据：`import-recovery.json`、`import-recovery-trace.zip`、`import-1-all-sessions.png`、`import-2-all-sessions.png`；来源 `src/mvp/runtime.js` 的 imported/transferResults 及 `Assistant.jsx` Navigator。

### F-OBJ-02 · pending repair · 首页助手入口显示新聊天但沿用导入身份

例子：打开任一导入对话→首页→打开助手，标题变为“新聊天”，正文仍显示刚导入的内容。同一身份在两个入口显示不一致，用户无法判断将继续旧对话还是开启新对话。

推荐：公开入口选择应明确保留当前会话并显示真实标题，或按其“新会话”目标生成独立空会话；系统决定和保存对象身份，不让用户手工找 ID。与 F-OBJ-01 一并核对首页、会话列表、新建与导入结果四个消费者。

证据：`cases2.json`、`cases2-trace.zip`、`import-1-revisit-assistant.png`、`import-2-revisit-assistant.png`。
