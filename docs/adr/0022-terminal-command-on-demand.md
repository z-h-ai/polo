# 终端命令按需启用，内置 AI 无需终端配置

Status: accepted for POO-192, 2026-10-29。用户确认：在区分内置 AI 与外部终端命令后，按推荐方案处理。

## 背景与来源

CLI、headless server、Agent worker 和 Bun 随客户端打包。`main/index.ts` 解析内置
运行时并给内部 Agent 设置命令路径；应用 SDK 经 `app-sdk-bridge.ts` 调用 `/ai/query`。
二者均不依赖 `~/.local/bin/polo` 或用户 shell profile。

原实现的首次启动询问和普通设置卡片，把外部命令入口表现成客户端能力的准备步骤。
本任务最初的未提交候选改为静默自动启用，但仍在失败/冲突时打断启动。
该候选已被用户在本次讨论中确认的按需方案替代，不作为当前产品依据。

## 决策

- 普通启动不检查、不安装、不修复外部命令，不因它显示任何首启弹窗。
- 普通设置页移除终端卡片，同时移除挂载时的终端状态 IPC 查询。
- macOS 打包客户端在“帮助 → polo 终端命令…”提供独立管理入口。
  打开入口只检查状态；用户明确选择启用、修复或停用后才修改受管理文件。
- 对话框说明内置 AI 无需启用命令，并在启用前说明 launcher 与 PATH 写入。
- 冲突仅在该入口呈现，允许重新检查；绝不覆盖用户自有命令或无归属文件。
- 保留已有命令与兼容接口；停用仅移除受管理入口，不影响内置运行时/AI。
- 保留显式命令行管理入口 `--polo-terminal-integration install|repair|uninstall|status`。

## 范围与兼容

本次不更改 Windows/Linux 或显式 shell 安装脚本的安装契约，也不主动删除用户机器
已经存在的 launcher、shell 区块或旧 dismissal 记录。macOS 帮助入口继续使用既有
事务式、归属校验的 terminal-integration 实现；旧字段保留用于兼容，不再控制启动。

## 验证边界

状态/冲突/显式操作/异常通过定向测试；设置与帮助入口提供隔离 Electron 运行证据。
这不代表完整安装包、真实计费或正式发布验收。证据在本任务交付报告中列出。
