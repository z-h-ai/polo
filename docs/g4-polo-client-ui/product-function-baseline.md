# Polo G1 产品功能基线

状态：已确认（2026-08-10）

日期：2026-08-09

范围：Polo 客户端、企业组织管理端、创作者工作台、平台运营端

本文把 POL-68 已确认的概念转换为当前版本的操作级功能范围。它只回答“谁可以在哪里完成什么，并得到什么业务结果”，不规定页面布局、点击顺序、路由、视觉或具体 API。

## 1. 范围标记

| 标记 | 含义 | 是否进入当前版本 |
| --- | --- | --- |
| 必须 | 没有该能力就无法成立已确认的产品模型或完成核心闭环 | 是 |
| 简化 | 当前版本需要，但按已确认边界使用最小可用形态 | 是 |
| 后续 | 有合理价值，但不阻塞当前产品模型和核心闭环 | 否 |
| 不做 | 已明确不属于当前产品方向，实施时不得顺带加入 | 否 |

每项功能只有一个权威写入口。其他入口可以显示状态或提供带上下文跳转，但不能重复实现同一写流程。

## 2. 当前版本核心闭环

当前版本必须能端到端完成以下四个闭环：

1. **个人消费闭环**：普通用户注册 → 自动获得我的空间 → 加入一个或多个圈子 → 获得已分发作品 → 主动启用/打开 → 由个人承担算力。
2. **企业消费闭环**：用户创建或加入企业 → Owner/Manager 导入并分发作品 → Member 在企业空间使用 → 数据和费用留在企业。
3. **创作者供给闭环**：平台授予创作者资格 → 创作者创建圈子和作品 → 版本通过检查并发布 → 分发到圈子 → 成员获得使用权 → 创作者查看聚合经营结果。
4. **平台治理闭环**：平台发现资格、支付、运行或安全异常 → 进入行动队列 → 经重新验证和原因记录执行治理 → 全局授权及时生效 → 审计可追溯。

## 3. Polo 客户端（成员工作台）

Polo 客户端是成员消费入口。当前重构以现有桌面客户端为实施对象；浏览器只承载注册、登录、企业邀请确认、审批结果和客户端下载引导，不提供成员工作台；手机网页也不能直接使用 Apps/Skills/Polo 助手。

## 4. 企业组织管理端

企业组织管理端是 Enterprise Owner/Manager 的唯一企业管理写入口。Owner 与 Manager 使用同一套功能结构，具体操作权限不同。

| ID | 功能 | 使用者 | 范围 | 业务结果 |
| --- | --- | --- | --- | --- |
| ENT-00 | 创建企业 | 完成基础验证的普通用户 | 必须 | 创建 Enterprise 和对应 ProductSpace，创建者成为唯一 Owner |
| ENT-01 | 查看企业概览、状态和待处理事项 | Owner/Manager | 必须 | 管理员知道成员是否已具备可用工作工具 |
| ENT-02 | 编辑企业基础资料 | Owner | 必须 | 企业名称、用途和关键设置有唯一责任人 |
| ENT-03 | 创建、撤销、审批和查看指定邀请或快速共享邀请 | Owner/Manager | 必须 | 指定成员可直接确认加入；共享链接申请经审批后加入；所有新成员默认是 Member |
| ENT-04 | 查看企业成员、角色和状态 | Owner/Manager | 必须 | 管理员理解当前访问关系 |
| ENT-05 | 调整成员角色、暂停、恢复或移除成员 | Owner | 必须 | 高风险成员管理只由 Owner 执行并审计 |
| ENT-06 | 原子转让唯一 Owner | Owner | 必须 | 所有权转给有效 Manager，原 Owner 自动成为 Manager |

## 5. 创作者工作台

创作者工作台是创作者作品、圈子和经营管理的唯一写入口。有效创作者可以管理自己的作品并创建圈子；圈子范围内只有 Creator Owner，不提供 Creator Manager 或创作者子账号。

### 5.1 资格、圈子与成员

| ID | 功能 | 使用者 | 范围 | 业务结果 |
| --- | --- | --- | --- | --- |
| CRE-01 | 查看创作者资格、限制状态和只读历史 | 有效/暂停/撤销创作者 | 必须 | 资格失效后仍可查看圈子、作品、订单、结算、原因、申诉和导出，但不能新增或修改 |
| CRE-02 | 创建一个或多个圈子 | 有效创作者 | 必须 | 创建成功后，该创作者成为具体圈子的 Creator Owner |
| CRE-03 | 编辑圈子介绍和允许范围内的加入模式 | Creator Owner | 必须 | 空圈可自由切换；免费/仅邀请切换只影响后续加入；存在付费成员或订单时不能直接退出付费模式 |
| CRE-04 | 创建定向邀请、通用加入链接和二维码 | Creator Owner | 必须 | 免费或付费按加入规则处理；仅邀请圈子的通用链接/二维码只产生待审批申请 |
| CRE-05 | 查看圈子成员基础身份和资格状态 | Creator Owner | 必须 | 创作者可以经营会员，但不能查看用户业务内容或余额 |
| CRE-06 | 赠送免费资格、暂停风险成员或设置到期不续费 | Creator Owner | 必须 | 成员处理遵守原因、退款和剩余权益规则 |
| CRE-07 | 设置订阅价格和后续周期涨价 | Creator Owner | 必须 | 当前已付周期不受影响，涨价需要成员确认 |
| CRE-08 | 发起关闭圈子并处理续费和退款 | Creator Owner | 必须 | 圈子进入 `closing`，停止新加入和续费；平台核清权益和资金责任后确认 `closed` |
| CRE-09 | 圈子会员等级、分组和差异化作品包 | Creator Owner | 不做 | 当前所有有效成员共享同一分发范围 |
| CRE-10 | 创作者子账号、协作者和委派管理 | Creator Owner | 不做 | Creator Owner 独自承担管理责任 |
| CRE-11 | 普通用户自助申请并自动成为创作者 | 普通业务账号 | 不做 | 当前资格由平台线下审核后授予，不建设开放申请流程 |

## 8. 跨版本明确不做

以下项目已经明确排除，不进入 G2/G3 原型或当前实施任务：

- Creator Circle 作为第三类可切换空间。
- 企业关注、加入或订阅创作者圈子。
- 普通用户直接上传、旁加载来源不明 App/Skill。
- 公开应用市场、公开创作者市场和关注动态信息流。
- Creator Manager、创作者子账号或协作者。
- 圈子会员等级、成员分组和差异化作品包。
- 企业部门树、人事系统同步和多层审批组织架构。
- 平台级 Work Item、“继续工作”或“待人工确认”聚合。
- 企业委托开发的站内订单、合同和交付项目管理。
- 平台管理员模拟用户登录或默认读取租户业务内容。
- Web App 任意调用用户电脑或个人目录中的 Skills。
- 企业目录自动继承成员在我的空间中的个人授权。

## 10. 已确认的产品事项

现有定义已经能够推导绝大多数功能范围。以下三项非显而易见问题已由产品用户集中确认：

### G1-Q1 — 本轮成员端覆盖哪些设备

确认结论：本轮重构只把现有 Polo 桌面客户端作为“Polo 客户端”的业务使用入口；浏览器和手机只实现注册、登录、邀请确认、审批结果与客户端下载引导等轻量页面，不提供成员工作台，也不允许直接使用 Apps/Skills/Polo 助手。

影响：如果三端都进入本轮，G2/G3、会话同步、文件能力、离线策略和验收矩阵会显著扩大，不能继续使用当前 P01/P02/P03 拆分。

### G1-Q2 — 当前空间选择是否跨设备同步

确认结论：不跨设备同步。每台设备保留自己的最后选择；数据、授权和会话仍由 ProductSpace 隔离。用户在电脑选择企业 A，不改变手机或另一台电脑的当前空间。

影响：若要求同步，需要服务端保存易变的当前空间偏好，并定义多设备同时切换和运行中的冲突规则。

### G1-Q3 — 当前版本是否建设统一通知中心

确认结论：不建设统一通知中心。当前版本只要求各入口提供与当前任务相关的状态、错误和待处理提示；重要安全、价格、资格和订单事件通过既有外部通知渠道加入口内提示完成。统一跨入口通知中心列入后续版本。

影响：若要求统一通知中心，需要新增通知对象、已读状态、投递偏好、跨账号/空间路由和多端同步，形成独立平台能力。

以上三项全部确认，本文功能范围直接进入 G2，G1 已通过。
