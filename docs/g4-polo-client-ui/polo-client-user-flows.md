# Polo 客户端用户流程

状态：产品流程已确认（2026-08-10）；可视化画布由用户单独维护

日期：2026-08-09

依据：`product-function-baseline.md`、`user-flows-permissions-and-states.md`、`product-space-contract.md`

## 1. 产品入口定义

Polo 客户端是成员消费 AI 能力的桌面工作台，负责登录入口、会话恢复和已登录业务壳。系统浏览器只承载企业邀请落地、付费圈子结算、企业/创作者管理、充值账单和复杂账号责任处理，不提供成员工作台；手机成员端不进入本轮页面与交互实现。

客户端负责：

- 使用当前 ProductSpace 提供的 Apps、Skills 和 Polo 助手。
- 管理“我的空间”中的圈子关系和个人订阅。
- 在“我的空间”和企业空间之间安全切换。
- 承载文件、本地 Workspace、运行状态等下沉技术能力。
- 按账号真实身份提供企业管理端或创作者工作台的带上下文跳转。

客户端不负责企业管理、创作者生产发布或平台治理写操作。

## 3. 核心流程

### PC-F01：新用户第一次进入 Polo

**角色**：没有企业邀请的新注册用户。

**主流程**：

1. 用户注册或登录 Polo。
2. 已登录用户重新打开客户端时，系统恢复有效账号会话；会话失效时回到登录或恢复账号流程。
3. 系统识别这是普通业务账号。
4. 系统查找该账号一一对应的“我的空间”；不存在时自动创建。
5. 用户直接进入“我的空间”首页，不需要先创建或加入组织。
6. 首页以当前可用 App 为核心，固定展示 Polo 助手和最多 5 个用户配置的工作 App；“文件”和“任务与结果”作为系统工具，“全部 Apps”和“我的圈子”作为次级入口。
7. 首页不展示 Skills 摘要、最近结果、内容变化、通用聊天输入框、平台级“继续工作”或统一任务队列。

**异常与恢复**：

- “我的空间”仍在创建：显示正在准备并自动重试，不能创建第二个空间。
- 账号被暂停：不进入任何空间，显示受限原因和恢复渠道。
- 首次目录加载失败：显示明确失败状态，不展示其他账号或空间的缓存内容。

**成功结果**：无邀请用户也能直接开始使用 Polo。

### PC-F02：在“我的空间”使用 App

**角色**：“我的空间”用户。

**主流程**：

1. 用户进入“我的空间”，客户端加载 Polo 内置 App 和已加入圈子明确分发的 App。
2. 用户查看 App 名称、创作者或圈子来源、稳定版本和当前可用状态。
3. 用户主动打开 App；加入圈子本身不会自动打开或激活 App。
4. App 在“我的空间”的身份、数据和权限范围内运行。
5. 用户在 App 或 Polo 助手中明确选择本机材料、执行任务并取得结果；客户端不提供独立的文件上传入口。
6. 数据、文件、结果、历史和算力费用归用户个人。
7. 已开始的执行固定使用启动版本；新稳定版本从下次启动生效。

**客户端运行能力**：

- 用户侧只看到可使用、准备中、更新中、运行中、已停用和不可用，不区分远程 App、本地 App 或沙箱 App。
- 点击 App 原则上直接打开；下载、缓存和 Runtime 准备属于客户端内部技术过程。
- 本地 Runtime 按账号、ProductSpace 和作品实例隔离；同一 App 在个人与企业中的状态和日志不能互相覆盖。
- 准备、更新或运行失败时，用户可以看到可理解的错误和不含业务内容的必要排障日志。
- Sources、Automations 和 Browser 只保留在 Polo 助手内部；本地 Workspace、模型、终端和权限模式只作为会话或高级上下文。全局最近文件由“文件”系统工具承载，以上能力都不主导普通成员首页。

**个人控制**：

- 用户可以隐藏、停用或从常用入口移除单个圈子 App，而不退出圈子。
- 用户可以从圈子作品列表恢复仍然有效的 App。
- 普通用户不能上传或旁加载来源不明的 App。

**异常与恢复**：

- 授权撤销、停止分发或订阅失效：停止新启动，并说明原因。
- 严重安全风险被平台阻断：所有空间立即禁止启动该版本。
- 已导出或明确保存到“我的空间”的结果继续保留。
- App 内部历史遵守其数据保留声明，但不能借历史页面绕过授权继续执行。

**成功结果**：用户只消费经过授权的 App，个人数据与费用留在“我的空间”。

### PC-F03：加入和管理创作者圈子

**角色**：普通业务账号。

加入入口来自邀请链接、二维码或创作者分享，客户端不提供公开圈子市场。免费或邀请加入可以在客户端确认；付费加入在系统浏览器完成支付，成功后返回客户端圈子详情。

**免费或邀请加入**：

1. 用户打开邀请、加入链接或二维码。
2. 系统展示圈子、创作者、加入方式和分发内容说明。
3. 用户确认加入。
4. 系统建立圈子成员关系，圈子出现在“我的圈子”。
5. 加入成功后进入圈子详情，展示“你已获得以下 Apps 和 Skills”。
6. 用户可以从圈子详情打开 App 或启用 Skill。
7. 该圈子明确分发的 Apps/Skills 进入“我的空间”目录，但不自动打开 App 或启用 Skill。

**付费加入**：

1. 用户查看价格、计费周期和续费规则。
2. 用户确认购买。
3. 支付成功后成员资格生效，作品进入“我的空间”。
4. 当前客户端清楚展示圈子订阅价格、周期和续费规则；AI 算力归属继续由内部契约分别记账，常规页面暂不持续展示，后续充值功能另行设计。
5. 支付成功后同样进入圈子详情，展示已获得的 Apps/Skills 和下一步操作。

**退出与续费**：

- 取消续费：当前已付周期继续可用，到期后失效。
- 立即退出：确认后立即撤销圈子作品授权。
- 续费失败：进入宽限期；补款成功恢复，宽限期结束后失效。
- 允许恢复时，用户通过补款或重新加入恢复资格。

**异常与恢复**：

- 链接失效或圈子停止加入：不建立成员关系。
- 已经加入：打开现有圈子关系，不重复创建。
- 支付结果未知：显示处理中，不重复扣款或授权。
- 确认前价格变化：要求按新价格重新确认。
- 退款或拒付异常：保留处理中状态，交由平台运营处理。

**成功结果**：多个圈子的作品在同一个“我的空间”聚合，圈子本身不进入空间切换器。

### PC-F04：启用 Skill 并使用 Polo 助手

**角色**：“我的空间”用户。

**主流程**：

1. 用户查看 Polo 内置和已加入圈子分发的 Skills。
2. 用户根据名称、创作者、来源圈子和状态明确启用某个 Skill。
3. Skill 的授权属于当前 ProductSpace；用户启用状态按“账号 + ProductSpace + Skill”保存，并在该用户设备间同步，不会替其他企业成员启用。
4. 下载、缓存或其他设备准备状态属于客户端内部实现，不形成第二套用户可见的启用状态。
5. 用户打开 Polo 助手并创建或继续“我的空间”的对话。
6. Polo 助手只调用当前空间中已经启用的 Skills。
7. 对话、附件、文件、上下文和费用保存在“我的空间”。
8. 内部计量归属为用户个人；当前助手常规页面不持续展示算力承担说明。

**异常与恢复**：

- 多个圈子提供同名 Skill：始终显示来源。
- 助手可以根据配置自动根据任务需要调用skill。
- Skill 在执行前失效：不调用，并提示选择其他能力。
- Skill 被紧急全局阻断：终止相关调用并显示安全原因；已保存历史结果不自动删除，但标记来源版本已被阻断。

**成功结果**：Polo 助手作为“我的空间”的独立内置 App 运行，不读取任何企业对话、文件或 Skills。

### PC-F05：接受企业邀请并进入企业空间

**角色**：收到企业邀请的普通用户。

**接受邀请**：

1. 用户在浏览器打开指定邀请链接或快速共享链接。
2. 邀请落地页展示企业名称、邀请人、邀请状态和默认 Member 身份；该页面不是 Web 工作台。
3. 用户注册或登录 Polo，认证完成后返回原邀请页。
4. 指定成员邀请在身份匹配并确认后直接加入；快速共享邀请提交后等待 Owner/Manager 审批。
5. 加入成功页引导用户在电脑上下载 Polo 客户端，或在已安装时打开客户端。
6. 用户使用同一账号登录桌面客户端后，企业空间出现在空间切换器中。
7. 用户可以进入企业空间，也可以继续留在“我的空间”；加入操作不强制改变其他设备的当前空间。

**创建企业的交接流程**：

1. 完成基础验证的用户从客户端选择创建企业。
2. 客户端跳转企业组织管理端，不复制企业创建逻辑。
3. 创建成功后，用户成为唯一 Owner。
4. 创建成功页提供“返回 Polo 客户端”。
5. 客户端收到刷新信号后显示新企业空间，但不强制立即切换。
6. 客户端未打开时，用户下次启动后正常看到新企业空间。

**异常与恢复**：

- 邀请过期、取消或使用完：不建立成员关系。
- 快速共享邀请仍在审批：可以下载并登录客户端，但在批准前不显示企业空间。
- 指定邀请的登录账号与受邀邮箱或手机号不匹配：提示切换账号。
- 用户已经是有效成员：返回现有关系，不重复加入。
- 用户已被该企业暂停：邀请不能绕过暂停。
- 接受成功但目录加载失败：成员关系保留，允许重试，不混入个人目录。

**成功结果**：用户获得企业空间消费入口，企业写操作继续留在组织管理端。

### PC-F06：在个人和企业空间之间安全切换

**角色**：拥有多个 ProductSpace 的用户。

**空间选择器**：

- 只显示“我的空间”和用户仍然有效加入的企业空间。
- 不显示 Creator Circle、创作者工作台、平台运营端或本地 Workspace。

**没有运行项时**：

1. 用户选择目标空间。
2. 系统验证目标空间访问权。
3. 系统原子切换当前 ProductSpace。
4. 客户端整体刷新 App 目录、Skills、Polo 助手、会话、文件、权限和运行上下文；内部计量归属随 ProductSpace 切换，但不作为常驻说明展示。
5. 全部上下文切换完成后才展示目标空间首页。

**存在运行项时**：

1. 用户发起切换，系统发现当前 App、Polo 助手或 AI 仍在运行。
2. 弹窗列出所有运行项，并说明必须先终止当前空间运行项。
3. 主操作为“终止全部并切换”，不要求用户逐项操作。
4. 终止过程中显示每个运行项的状态。
5. 全部终止成功后才提交空间切换。
6. 任一项终止失败时保持原空间，提供“重试失败项”和“取消切换”。

**取消分支**：用户取消终止后留在原空间，任务继续运行，所有上下文保持不变。

**异常与恢复**：

- 目标企业访问权失效：不进入目标空间，并移除或标记不可用。
- 目标空间加载失败：不能展示新旧空间混合内容；允许重试或返回原空间。
- 切换只影响当前账号当前设备，其他设备不跟随。
- 从客户端首页切换后进入目标空间首页。
- 从 Polo 助手中切换后进入目标空间的助手会话列表或新对话页，不自动打开目标空间上次对话。
- Polo 助手页面持续显示当前空间名称，不持续显示付款方或 AI 算力承担说明。

**成功结果**：旧空间没有后台运行项，目录、数据、权限和付款主体不会串空间。

### PC-F07：在企业空间使用 App、Skill 和 Polo 助手

**角色**：Enterprise Member、Manager 或 Owner；在客户端中均以成员消费身份操作。

**使用企业 App**：

1. 用户进入企业空间。
2. 客户端只展示企业已导入、启用并向该用户分发的 App。
3. 用户打开 App，使用企业身份和权限执行任务。
4. 文件、输入、结果、历史和费用全部归企业。

**使用企业 Skill 和 Polo 助手**：

1. 用户只看到企业已经分发的 Skills。
2. 用户明确启用需要的 Skill。
3. 用户打开该企业独立的 Polo 助手实例。
4. 助手只调用企业授权 Skills，只读取企业允许的数据和文件。
5. 对话、附件和上下文保存在企业空间；内部计量授权按企业空间解析，但助手界面不展示算力承担说明。

**强约束**：

- 企业不继承成员个人圈子授权。
- 企业作品由 Owner/Manager 在组织管理端导入和分发。
- 同一作品在个人与企业空间中的实例、版本、状态和历史互不覆盖。
- 切回“我的空间”后，个人助手不出现企业历史。

**成功结果**：成员能够消费企业工具，企业数据和费用不进入个人空间。

### PC-F08：权限或作品失效后的退出与保留

**角色**：正在使用企业或圈子作品的用户。

**企业成员被暂停或移除**：

1. 客户端发现用户失去当前企业访问权。
2. 系统显示具体原因和“联系企业管理员”入口。
3. 系统停止新的 App、Skill 和 Polo 助手操作，并终止企业运行项。
4. 系统清除可操作的企业上下文，安全返回“我的空间”。
5. 企业数据、文件和结果继续归企业，不迁移到个人空间。

**企业欠费、治理暂停或关闭中**：

- 停止新的 App/AI 执行并终止该企业空间中的活动执行；恢复后不自动重启。
- Member 和 Manager 不能绕过限制。
- Owner 通过企业组织管理端处理账单、导出或申诉。
- 限制解除时，只恢复原本仍有效的成员、目录和启用状态。

**圈子或作品失效**：

- 立即停止新启动或调用。
- 已导出或明确保存的结果继续保留。
- 客户端暂时保留不可用作品说明，显示退出圈子、订阅到期、停止分发或平台阻断等具体原因，而不是无痕消失。
- 旧链接、缓存和本地启用状态不能绕过服务端授权。

**安全降级**：如果“我的空间”暂时无法加载，显示安全受限页，不继续展示企业内容。

**成功结果**：失效权限立即生效，同时保留属于数据所有方的历史和必要记录。

## 4. 辅助与异常流程

### PC-F09：个人账号与管理入口

1. 用户打开账号与偏好，查看账号状态、安全、外观、通知、本机存储和授权记录；充值与个人费用功能后续另行设计。
2. 企业账单跳转企业组织管理端；创作者收入跳转创作者工作台。
3. 账号具备对应企业角色或有效创作者资格时显示可写管理入口；创作者资格暂停或撤销后仍显示只读责任处理入口，直到资产和财务责任完成交接或关闭。
4. 用户可以退出登录、重新登录或完成账号会话恢复；退出登录不删除本地业务数据。
5. 注销前必须处理 Enterprise Owner、Creator Owner 和未结财务责任；未完成时列出阻塞项。

### PC-F10：离线和运行中断网

1. 离线打开时，用户可以查看已保存在本机的历史结果、文件和目录说明。
2. 客户端明确提示缓存不是最新授权状态。
3. 离线时不能启动新的 App、Polo 助手或 AI 执行。
4. 运行中断网时，停止新的 AI/网络调用，任务进入“等待恢复或终止”。
5. 恢复网络后重新验证空间、授权、版本和付款主体，验证成功后才能继续。
6. 未知结果不能显示为成功。

### PC-F11：客户端契约不一致

1. 客户端启动或登录后校验 ProductSpace `contractVersion`。
2. 当前客户端无法安全理解服务端契约时，阻止进入业务界面。
3. 系统显示明确升级提示和升级帮助；未公开发布阶段不维持旧客户端降级运行。
4. 旧 Creator Space、Organization 或缓存不能被解释为当前空间，升级后旧授权与 Runtime 缓存直接失效重建。
5. 暂时无法升级时，只能查看帮助，不能继续执行可能串空间的操作。

## 5. 本入口明确不做

- 企业成员、邀请、作品分发、预算和账单管理。
- 创作者资格申请、圈子创建、成员经营、作品创建和发布。
- 平台订单、作品审批和全局治理。
- 公开应用市场、创作者关注和信息流。
- 平台级“继续工作”、统一待办或跨 App 工作项。
- 跨 ProductSpace 后台运行。
- Web App 任意调用用户电脑或个人目录中的 Skills。

## 6. 已确认的产品交互结论

- 首页以 Apps 为核心；Polo 助手是固定内置 App，Skills 和“我的圈子”下沉为次级入口。
- 首页固定 6 个快捷入口（Polo 助手 + 最多 5 个工作 App）；超出容量的作品始终可以在“全部 Apps”查找和直接打开。
- App 统一按 Web App 产品概念呈现，不向用户暴露安装、卸载、Runtime 或沙箱类型。
- 加入圈子后进入圈子详情，展示新获得的 Apps/Skills，但不自动打开或启用。
- 免费/邀请加入可在客户端确认；付费圈子在系统浏览器完成结算后返回客户端。客户端不提供公开圈子市场。
- Skill 启用状态按“账号 + ProductSpace + Skill”保存并跨该账号的设备同步；设备缓存和准备状态不形成第二套业务状态。
- 空间切换采用“终止全部并切换”，展示运行项和逐项终止状态；失败时只允许重试或取消。
- 从助手中切换空间后进入目标空间助手列表或新对话，不自动打开目标空间旧对话。
- 企业创建在组织管理端完成，并通过“返回 Polo 客户端”和目录刷新完成跨端交接。
- 权限失效时显示原因和处理入口；失效作品暂时保留不可用说明，避免无痕消失。
- Sources、Automations 和 Browser 只属于 Polo 助手内部，不进入客户端顶层导航或独立 App Tab。
- 账号与偏好在客户端内展示；企业/创作者管理、充值账单和复杂注销责任处理进入系统浏览器。
- 可视化画布由用户单独更新，不属于本文后续维护范围。
