# 02 - 用户角色与用户故事

## 主要用户角色

### R1：个人开发者
**画像**：日常使用 AI 代理进行编程、调试和自动化的软件开发者。

**目标**：
- 同时管理多个编程任务，获得 AI 辅助
- 连接项目特定的工具（GitHub、Linear、数据库）
- 按项目/工作区自定义代理行为
- 跨会话跟踪工作进展

**关键工作流**：
1. 为项目创建工作区 → 连接 GitHub MCP 来源 → 与代理讨论代码
2. 导入 Claude Code 技能 → 按项目规范自定义代理
3. 在后台运行长时间操作 → 检查状态 → 审查结果

### R2：团队负责人 / 高级用户
**画像**：跨多个项目和代理协调工作的技术负责人。

**目标**：
- 跨工作区监控和分拣代理会话
- 为重复性任务设置自动化
- 分享会话记录以实现知识传递

**关键工作流**：
1. 标记重要会话 → 分配状态（待办 → 进行中 → 完成）
2. 设置定时自动化（每日站会、每周总结）
3. 通过查看器与团队成员分享会话链接

### R3：DevOps / 基础设施用户
**画像**：在远程服务器上部署 Polo AI 以实现持久访问的用户。

**目标**：
- 在 VPS 上以无头模式运行 Polo AI
- 从多台机器访问会话
- 与 CI/CD 流水线集成

**关键工作流**：
1. 部署 Docker 容器 → 将桌面应用作为瘦客户端连接
2. 使用 CLI 客户端执行脚本化操作（`polo-ai run "Summarize this repo"`）
3. 通过 21 步集成测试验证服务器

### R4：多模型提供商用户 ⚠️ [待确认]
**画像**：希望使用多个 LLM 提供商（Claude、GPT、Gemini、Copilot）的用户。

**目标**：
- 在不同会话之间切换提供商
- 使用各提供商的特定功能（Google 搜索增强、Codex 模型等）
- 通过自定义端点路由（OpenRouter、Ollama、自托管）

**关键工作流**：
1. 添加多个 LLM 连接 → 设置每个工作区的默认连接
2. 代码任务使用 Claude，研究使用 Gemini，GitHub 工作流使用 Copilot
3. 连接本地 Ollama 处理隐私敏感工作

## 用户故事

### 会话管理
- US-001：作为一名开发者，我希望在工作区中创建多个聊天会话，以便我可以同时处理不同的任务。
- US-002：作为一名开发者，我希望在收件箱视图中查看所有会话及其状态指示，以便我可以优先安排工作。
- US-003：作为一名开发者，我希望能够标记重要会话，以便我以后可以快速找到它们。
- US-004：作为一名开发者，我希望会话具有 AI 生成的标题，这样我无需手动命名就能识别它们。
- US-005：作为一名开发者，我希望能够归档已完成的会话，以保持收件箱整洁。

### AI 交互
- US-006：作为一名开发者，我希望 AI 响应能够流式输出并实时展示工具执行过程，这样我可以跟踪代理的进展。
- US-007：作为一名开发者，我希望能在消息中附加文件（图片、PDF、Office 文档），以便代理可以处理丰富内容。
- US-008：作为一名开发者，我希望能在权限模式之间切换（Explore/Ask/Auto），以控制代理的自主程度。
- US-009：作为一名开发者，我希望能在对话中途中断并重定向代理，以纠正其方向。

### 来源与连接
- US-010：作为一名开发者，我希望通过向代理描述需求就能连接到 MCP 服务器、REST API 和本地文件系统。
- US-011：作为一名开发者，我希望粘贴 OpenAPI 规范或 MCP 配置 JSON 后，代理就能自动完成所有配置。
- US-012：作为一名开发者，我希望能够导入已有的 Claude Code 技能和 MCP 配置，这样就不需要重新创建。

### 工作区与自定义
- US-013：作为一名开发者，我希望能够创建具有独立设置、来源和技能的按项目划分的工作区。
- US-014：作为一名开发者，我希望能在应用级别和工作区级别自定义主题。
- US-015：作为一名开发者，我希望能够创建和管理专门的技能来塑造代理的行为。

### 自动化
- US-016：作为一名团队负责人，我希望能够安排定时的提示（每日站会、每周总结），这样我就不需要记住这些事。
- US-017：作为一名团队负责人，我希望在标签变更时触发自动化，以便紧急事项能立即得到关注。

### 远程与 CLI
- US-018：作为一名 DevOps 用户，我希望在远程服务器上运行 Polo AI 并从桌面连接。
- US-019：作为一名 DevOps 用户，我希望在 CI/CD 流水线中使用 CLI 执行脚本化操作。
- US-020：作为一名 DevOps 用户，我希望使用 `run` 命令执行独立的、一次性的代理任务。
